## The idea

Saving work in Git is always the same loop: change some files, check what changed, stage the changes, then commit them.

```bash
git status                       # 1. What changed?
git add .                        # 2. Stage the changes
git commit -m "Add login page"   # 3. Save them as a commit
```

## How it works

### git status

Shows the state of your working directory:

- **Untracked files:** new files that Git has never tracked.
- **Changes not staged for commit:** changed files that aren't staged yet.
- **Changes to be committed:** staged changes. They will go into the next commit.

It also tells you which branch you're on. Run it often.

### git add

```bash
# Stage one file.
git add index.js

# Stage all changes in the current folder and its subfolders.
git add .
```

`git add .` stages new, changed and deleted files. Run it from the root folder to stage everything.

### Unstage a file: git reset

```bash
git reset index.js
```

This takes the file out of the staging area, so it's back to modified. **The changes stay in the file.** It doesn't delete or undo anything.

### git commit

```bash
git commit -m "Fix price rounding on the cart page"
```

Saves a snapshot of the **staged** changes in the history. Changes that aren't staged are left out. Write a message that says what the commit does, so the history is easy to read later.

### git log

```bash
# The full history: ID, author, date and message of every commit.
git log

# A short history: one line for each commit.
git log --oneline
```

The newest commit is at the top. `git log --oneline` looks like this:

```text
a1b2c3d (HEAD -> main) Fix price rounding on the cart page
9f8e7d6 Add login page
4c5d6e7 First commit
```

The short ID at the start (`a1b2c3d`) is what you give to commands like `git checkout`, `git revert` and `git cherry-pick`. `HEAD -> main` shows where you are: on `main`, at its latest commit.

<Callout title="Remember this" type="success">
  - The loop: `git status` → `git add` → `git commit -m "message"`.
  - `git add <file>` stages one file. `git add .` stages everything in the current folder and below.
  - `git reset <file>` **unstages** a file. The changes stay in the file.
  - `git commit` saves only what is **staged**.
  - `git log` shows the full history. `git log --oneline` shows the short ID and message of each commit.
</Callout>
