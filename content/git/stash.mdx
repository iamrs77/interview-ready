## The idea

`git stash` saves your **uncommitted changes** aside for a while, without committing them, and gives you a clean working directory.

Say you're halfway through a feature, and an urgent bug comes in on `main`. Your work isn't ready to commit, and you don't want it to come with you to `main`. Stash it, fix the bug, come back, and take your work out of the stash.

## How it works

### Save and list

```bash
# Save your uncommitted changes and clean the working directory.
git stash

# See all saved stashes. The newest one is stash@{0}.
git stash list
```

`git stash list` looks like this:

```text
stash@{0}: WIP on rohit: a1b2c3d Add login form
stash@{1}: WIP on main: 9f8e7d6 Fix price rounding
```

Each line shows the branch you were on and its latest commit at that time. WIP means "work in progress".

**New files are not stashed by default.** `git stash` only saves changes to files Git already tracks. To stash new (untracked) files too, use `git stash -u`.

### Get the changes back

```bash
# Apply the newest stash, and remove it from the list.
git stash pop

# Apply a specific stash, and remove it from the list.
git stash pop stash@{1}

# Apply a specific stash, but keep it in the list.
git stash apply stash@{1}
```

<Callout title="Remember this" type="success">
  - `git stash` saves **uncommitted** changes aside and cleans the working directory.
  - New (untracked) files are **not** stashed unless you use `git stash -u`.
  - `git stash list` shows the stashes. The newest is `stash@{0}`.
  - `git stash pop` applies **and removes** the stash. `git stash apply` applies and **keeps** it.
</Callout>
