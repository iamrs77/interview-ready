## The idea

A **branch** is a separate line of work. You make a branch for each feature or bug fix, so you can work on it without touching `main`. When the work is done, you merge it back into `main`.

Think of a **draft copy of a document**. You make your edits on the copy, and the real document only changes when the draft is ready.

Under the hood, a branch is just a **name that points to a commit**. Each new commit moves the name forward. That's why branches are quick and cheap to make.

## How it works

### See, create and switch branches

```bash
# See all branches, local and remote. * marks the one you're on.
git branch -a

# Create a new branch, but stay on the current one.
git branch feature-login

# Switch to an existing branch.
git checkout feature-login

# Create a new branch and switch to it, in one step.
git checkout -b feature-login
```

`git branch -a` looks like this:

```text
* feature-login
  main
  remotes/origin/HEAD -> origin/main
  remotes/origin/main
```

The `remotes/origin/...` lines are the branches on GitHub, as Git saw them at your last `git fetch` (see [Push, Pull and Fetch](./push-pull-fetch.mdx)).

### Delete a branch

```bash
# Safe delete. Git refuses if the branch has commits that aren't merged.
git branch -d feature-login

# Force delete, even if the branch has commits that aren't merged.
git branch -D feature-login
```

Use `-d` by default. Use `-D` only when you're sure you don't need that work anymore. Both delete the **local** branch only.

<Callout title="Remember this" type="success">
  - A branch is a **separate line of work**, and under the hood just a name that points to a commit.
  - `git branch -a` shows local and remote branches. `*` marks the current one.
  - `git branch <name>` creates a branch. `git checkout <name>` switches to it.
  - `git checkout -b <name>` creates a branch **and** switches to it.
  - `git branch -d` is the safe delete. `git branch -D` force deletes, even unmerged work.
</Callout>
