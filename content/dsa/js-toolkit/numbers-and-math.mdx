## The idea

JavaScript has **one type for all numbers**. `3`, `-7` and `2.5` are all the same `number` type. That keeps things simple, but it brings a few traps: dividing never gives a whole number by itself, some decimals are slightly off, and very big whole numbers lose their last digits.

An everyday comparison: you can't write 1/3 exactly as a decimal. You write 0.3333 and stop somewhere. The computer has the same problem with 0.1: it can't store it exactly, so it keeps the nearest value it can. Most of the time you never notice. In an interview, you need to know when you will.

## Math methods

All of these are **O(1)**, except `Math.max` and `Math.min`, which look at each of the k numbers you pass in.

| Method | What it does | Example | Cost |
| --- | --- | --- | --- |
| `Math.floor(x)` | Round **down** | `Math.floor(4.9)` → `4` | O(1) |
| `Math.ceil(x)` | Round **up** | `Math.ceil(4.1)` → `5` | O(1) |
| `Math.round(x)` | Round to the nearest. .5 goes up | `Math.round(4.5)` → `5` | O(1) |
| `Math.trunc(x)` | Cut off the decimals (towards 0) | `Math.trunc(-4.9)` → `-4` | O(1) |
| `Math.abs(x)` | Distance from 0 (drops the minus) | `Math.abs(-5)` → `5` | O(1) |
| `Math.max(a, b, ...)` | The biggest | `Math.max(1, 5, 3)` → `5` | O(k) |
| `Math.min(a, b, ...)` | The smallest | `Math.min(1, 5, 3)` → `1` | O(k) |
| `Math.pow(a, b)` or `a ** b` | a to the power of b | `2 ** 3` → `8` | O(1) |
| `Math.sqrt(x)` | Square root | `Math.sqrt(16)` → `4` | O(1) |
| `Math.sign(x)` | -1, 0 or 1 | `Math.sign(-3)` → `-1` | O(1) |
| `Math.random()` | Random number from 0 up to, not including, 1 | `Math.random()` → `0.7302...` | O(1) |

`Math.round` always sends .5 **up**, towards the bigger number: `Math.round(-2.5)` is `-2`, not `-3`.

## Turning text into numbers

**d** = number of digits.

| Method | What it does | Example | Cost |
| --- | --- | --- | --- |
| `Number(text)` | Text to number. The whole text must be a number | `Number("42")` → `42`, `Number("42px")` → `NaN` | O(d) |
| `parseInt(text)` | Read the whole number at the start of the text | `parseInt("42px")` → `42` | O(d) |
| `parseInt(text, 2)` | Read the text as base 2 (binary) | `parseInt("101", 2)` → `5` | O(d) |
| `parseFloat(text)` | Read a decimal number | `parseFloat("3.14")` → `3.14` | O(d) |
| `String(number)` | Number to text | `String(42)` → `"42"` | O(d) |
| `number.toString(2)` | Number to binary text | `(5).toString(2)` → `"101"` | O(d) |
| `number.toFixed(2)` | Round to 2 decimals. Gives **text** | `(3.14159).toFixed(2)` → `"3.14"` | O(d) |
| `Number.isInteger(x)` | Is x a whole number? | `Number.isInteger(5.0)` → `true` | O(1) |
| `Number.isNaN(x)` | Is x `NaN` (not a number)? | `Number.isNaN(NaN)` → `true` | O(1) |

`+` with a string **joins text**, while `*`, `-` and `/` turn the text into a number first. This catches people who read digits from a string.

```js
console.log("3" + 4); // 34
console.log("3" * 4); // 12
console.log(Number("3") + 4); // 7

console.log(Number("12abc")); // NaN
console.log(parseInt("12abc")); // 12

// An empty string becomes 0, not NaN.
console.log(Number("")); // 0

// NaN is not equal to anything, not even itself.
console.log(NaN === NaN); // false
console.log(Number.isNaN(NaN)); // true
```

## Integer division and remainders

`/` always gives the exact answer, decimals included. To get a whole number, round it yourself.

```js
console.log(7 / 2); // 3.5
console.log(Math.floor(7 / 2)); // 3
console.log(Math.trunc(7 / 2)); // 3
```

For positive numbers, `Math.floor` and `Math.trunc` give the same answer. For **negative** numbers they don't:

```js
// floor always goes DOWN, to the smaller number.
console.log(Math.floor(-7 / 2)); // -4

// trunc cuts off the decimals, so it goes towards 0.
console.log(Math.trunc(-7 / 2)); // -3
```

| `-7 / 2` is `-3.5` | Result | Same as |
| --- | --- | --- |
| `Math.floor(-3.5)` | `-4` | Python's `-7 // 2` |
| `Math.trunc(-3.5)` | `-3` | Java and C++ `-7 / 2` |

Which one to use:

- When the problem says **"truncate toward zero"** (like "Evaluate Reverse Polish Notation" or "Divide Two Integers"), use `Math.trunc`.
- For indexes, like the middle of a range in [Binary Search](../searching-sorting/binary-search.mdx), the numbers are never negative, so `Math.floor` is fine.

You may see `(a / b) | 0` in other people's code. It also cuts off the decimals, but it breaks for numbers above about 2 billion. Use `Math.trunc`.

### The remainder: %

`%` gives what is left over after dividing. Watch out: **the result keeps the sign of the left number**.

```js
console.log(7 % 3); // 1
console.log(-7 % 3); // -1

// So this "odd" check fails for negative numbers:
console.log(-3 % 2 === 1); // false

// Check odd with !== 0 instead.
console.log(-3 % 2 !== 0); // true
```

When you need a remainder that is never negative (for example, to wrap around a circle), add the divisor and take `%` again.

```js
function mod(number, divisor) {
    const remainder = number % divisor;

    // Turns -1 into 2 when dividing by 3. Positive answers stay the same.
    return (remainder + divisor) % divisor;
}

console.log(mod(-7, 3)); // 2
console.log(mod(7, 3)); // 1
```

### Working with digits

`% 10` gives the last digit. `Math.floor(number / 10)` drops the last digit.

```js
function sumOfDigits(number) {
    let sum = 0;

    while (number > 0) {
        const lastDigit = number % 10;
        sum = sum + lastDigit;

        // Drop the last digit: 123 becomes 12.
        number = Math.floor(number / 10);
    }

    return sum;
}

console.log(sumOfDigits(123)); // 6
```

**Time: O(log n).** The loop runs once per digit, and a number n has about log₁₀(n) digits. A number 10 times bigger needs just one more step.

## Infinity as a starting value

When you look for the smallest or the biggest value, start with `Infinity` or `-Infinity`. `Infinity` is bigger than every number, so the first real number always replaces it.

```js
const numbers = [4, -2, 9];

let smallest = Infinity;
let biggest = -Infinity;

for (const number of numbers) {
    smallest = Math.min(smallest, number);
    biggest = Math.max(biggest, number);
}

console.log(smallest); // -2
console.log(biggest); // 9
```

Why not start at 0? For the numbers `[4, 5, 9]`, a smallest that starts at 0 stays 0, and 0 isn't even in the list.

`Infinity` also works as "not found yet": if `smallest` is still `Infinity` after the loop, the list was empty, or no value passed your check.

You can also spread an array into `Math.max`, but with two traps:

```js
const numbers = [4, -2, 9];
console.log(Math.max(...numbers)); // 9

// An empty array gives -Infinity, not an error.
const empty = [];
console.log(Math.max(...empty)); // -Infinity
```

The second trap: with a very big array (above about 100,000 items) `Math.max(...numbers)` can crash with "Maximum call stack size exceeded". Interview inputs often go up to 100,000, so a plain loop is the safe choice.

## Floating point traps

```js
console.log(0.1 + 0.2); // 0.30000000000000004
console.log(0.1 + 0.2 === 0.3); // false
```

0.1 and 0.2 are both stored as the nearest value the computer can hold, and the tiny errors add up. So **never compare decimals with `===`**. Check that they are close enough instead.

```js
const sum = 0.1 + 0.2;

// Close enough: the gap is below Number.EPSILON, about 2 × 10⁻¹⁶.
// For bigger numbers, use a bigger gap, like 1e-9.
const gap = Math.abs(sum - 0.3);
console.log(gap < Number.EPSILON); // true

// toFixed rounds, but it gives back TEXT.
console.log(sum.toFixed(2)); // 0.30
console.log(typeof sum.toFixed(2)); // string

// Turn it back into a number with Number() (+ does the same).
console.log(Number(sum.toFixed(2))); // 0.3
```

For money, the usual fix is to work in **whole cents**: 10 + 20 = 30 is always exact.

## Big numbers: Number.MAX_SAFE_INTEGER

Whole numbers are exact only up to `Number.MAX_SAFE_INTEGER`: 9,007,199,254,740,991 (2⁵³ - 1, about 9 × 10¹⁵). Above that, numbers start to skip.

```js
const big = Number.MAX_SAFE_INTEGER;

console.log(big); // 9007199254740991
console.log(big + 1); // 9007199254740992
console.log(big + 2); // 9007199254740992
console.log(big + 1 === big + 2); // true
```

For numbers bigger than that, use **BigInt**: add an `n` after the number, or call `BigInt(number)`. Every digit stays exact. You can't mix BigInt and normal numbers: `10n + 1` throws a `TypeError`.

```js
const big = 9007199254740991n;

console.log(big + 2n); // 9007199254740993n
console.log(big * 10n); // 90071992547409910n

// Turn a normal number into a BigInt to mix them.
console.log(big + BigInt(1)); // 9007199254740992n
```

Where this bites in interviews: problems that say **"return the answer modulo 10⁹ + 7"**. Adding two such numbers is safe. But multiplying two of them gives about 10¹⁸, far above the safe limit, so the answer comes out wrong.

```js
const MOD = 1000000007;
const first = 999999999;
const second = 999999999;

// The product is about 10^18: too big, so the last digits are lost.
const wrong = (first * second) % MOD;
console.log(wrong); // 63

// BigInt keeps every digit.
const product = BigInt(first) * BigInt(second);
const right = Number(product % BigInt(MOD));
console.log(right); // 64
```

## Patterns you will write again and again

**Integer division**: `Math.floor` for indexes, `Math.trunc` when the problem says "toward zero".

```js
const left = 0;
const right = 9;
const middle = Math.floor((left + right) / 2);
console.log(middle); // 4

console.log(Math.trunc(-7 / 2)); // -3
```

**Take a number apart, digit by digit.** Here, to reverse it.

```js
function reverseNumber(number) {
    let reversed = 0;

    while (number > 0) {
        const lastDigit = number % 10;
        reversed = reversed * 10 + lastDigit;
        number = Math.floor(number / 10);
    }

    return reversed;
}

console.log(reverseNumber(1234)); // 4321
```

**Track the best answer so far**, starting from `Infinity`.

```js
const prices = [7, 1, 5, 3];
let cheapest = Infinity;

for (const price of prices) {
    if (price < cheapest) {
        cheapest = price;
    }
}

console.log(cheapest); // 1
```

**Wrap around a circular array** with `%`. Going back, add the length first so the index never goes below 0.

```js
const seats = ["A", "B", "C", "D"];
const length = seats.length;

const last = 3;
const next = (last + 1) % length;
console.log(seats[next]); // A

const first = 0;
const previous = (first - 1 + length) % length;
console.log(seats[previous]); // D
```

**Keep a big answer small** with modulo after every step.

```js
const MOD = 1000000007;
let ways = 1;

for (let i = 0; i < 100; i++) {
    // Doubling 100 times would pass the safe limit, so take % each time.
    ways = (ways * 2) % MOD;
}

console.log(ways); // 976371285
```

**A random whole number from min to max**, both included. Used in shuffles and Quickselect.

```js
function randomInt(min, max) {
    const count = max - min + 1;
    const offset = Math.floor(Math.random() * count);

    return min + offset;
}

// roll is 1, 2, 3, 4, 5 or 6
const roll = randomInt(1, 6);
```

More number problems (GCD, primes, powers) are in [Math and Matrices](../math-bits/math-and-matrices.mdx).

## Common mistakes

- **Expecting `7 / 2` to be 3.** It is 3.5. Round it with `Math.floor` or `Math.trunc`.
- **`Math.floor` on a negative division** when the problem wants "toward zero". Use `Math.trunc`.
- **`number % 2 === 1` to check odd.** It's `false` for negative numbers. Use `number % 2 !== 0`.
- **Comparing decimals with `===`.** `0.1 + 0.2 === 0.3` is `false`.
- **Forgetting that `toFixed` gives text.** `(0.5).toFixed(1) + 1` is `"0.51"`.
- **Starting a minimum at 0**, or a maximum at 0 when values can be negative. Use `Infinity` and `-Infinity`.
- **Adding text digits with `+`.** `"3" + 4` is `"34"`. Turn them into numbers first.
- **Multiplying big numbers past 2⁵³** without noticing. Take the modulo, or use BigInt.

## In the interview

Say it when you divide: "Division in JavaScript gives decimals, so I'll use `Math.trunc` to round toward zero, like the problem asks."

**Likely follow-up:** "What if the numbers get very large?"

**Answer:** "JavaScript numbers are exact only up to 2⁵³ - 1, about 9 × 10¹⁵. If the result can be bigger, I'll take the modulo after each step or switch to BigInt."

  - Start a minimum at `Infinity` and a maximum at `-Infinity`, never at 0.
