## The idea

A **sliding window** is a group of items **next to each other** (a subarray or a substring) that moves across the input. Instead of working out every group from scratch, you **add the item that comes in** on the right and **remove the item that goes out** on the left.

Think of the **step counter on your phone** that shows your steps for the last 7 days. Each new day, it adds today's steps and drops the day that is now 8 days old. It never adds up all 7 days again. That 7-day block is a window, and each day it slides one step.

## How it works

### A window is two indexes

A window is all the items from index `left` to index `right`, both included. Its length is **`right - left + 1`**.

```js
const numbers = [2, 1, 5, 1, 3, 2];

const left = 1;
const right = 3;

// slice's end is not included, so add 1.
const windowItems = numbers.slice(left, right + 1);

console.log(windowItems); // [ 1, 5, 1 ]
console.log(right - left + 1); // 3
```

| Index | 0 | 1 | 2 | 3 | 4 | 5 |
| --- | --- | --- | --- | --- | --- | --- |
| Value | 2 | 1 | 5 | 1 | 3 | 2 |
| Window | | `left` | in | `right` | | |

We use `slice` here only to show the window. Real solutions never copy the window: they keep a **running sum** or **counts** of what is inside.

### The slow way: start over for every window

**Problem:** find the biggest sum of 3 items in a row. In `[2, 1, 5, 1, 3, 2]`, the answer is 9 (5 + 1 + 3).

The brute force adds up every window from scratch:

```js
function maxSumSlow(numbers, windowSize) {
    let best = -Infinity;

    for (let start = 0; start + windowSize <= numbers.length; start++) {
        let sum = 0;

        // Add up the whole window again, every time.
        for (let i = start; i < start + windowSize; i++) {
            sum = sum + numbers[i];
        }

        best = Math.max(best, sum);
    }

    return best;
}

console.log(maxSumSlow([2, 1, 5, 1, 3, 2], 3)); // 9
```

**Time:** O(n · k), where k is the window size: about n windows, and k additions for each. But look at the windows `[2, 1, 5]` and `[1, 5, 1]`. They share 1 and 5, and we added those twice. That is the repeated work.

### Fixed-size window: add one, drop one

Add up the first window once. Then, for each slide, **add the item coming in and subtract the item going out**.

```js
function maxSumOfWindow(numbers, windowSize) {
    // Sum of the first window.
    let windowSum = 0;
    for (let i = 0; i < windowSize; i++) {
        windowSum = windowSum + numbers[i];
    }

    let best = windowSum;

    // Slide: one item comes in on the right, one goes out on the left.
    for (let right = windowSize; right < numbers.length; right++) {
        const comingIn = numbers[right];
        const goingOut = numbers[right - windowSize];

        windowSum = windowSum + comingIn - goingOut;
        best = Math.max(best, windowSum);
    }

    return best;
}

console.log(maxSumOfWindow([2, 1, 5, 1, 3, 2], 3)); // 9
```

| Window (indexes) | Items | Coming in | Going out | windowSum | best |
| --- | --- | --- | --- | --- | --- |
| 0 to 2 | 2, 1, 5 | | | 8 | 8 |
| 1 to 3 | 1, 5, 1 | 1 | 2 | 8 + 1 - 2 = 7 | 8 |
| 2 to 4 | 5, 1, 3 | 3 | 1 | 7 + 3 - 1 = **9** | 9 |
| 3 to 5 | 1, 3, 2 | 2 | 5 | 9 + 2 - 5 = 6 | 9 |

**Time:** O(n) · **Space:** O(1). Each slide is one addition and one subtraction, no matter how big the window is.

### Variable-size window: grow on the right, shrink on the left

Often the size isn't given. The problem says "the **longest**", "the **shortest**" or "**at most** 7". Then the window grows and shrinks. The pattern, in three steps:

1. **Grow:** move `right` one step. The new item joins the window.
2. **Shrink:** **while** the window breaks the rule, remove `numbers[left]` and move `left` forward.
3. **Measure:** the window follows the rule again. Update the answer with its length.

**Example:** the longest run of items in a row whose sum is at most 7. In `[2, 1, 5, 1, 3, 2]` the answer is 3 (`[1, 5, 1]` or `[1, 3, 2]`).

```js
function longestWithSumAtMost(numbers, limit) {
    let left = 0;
    let windowSum = 0;
    let best = 0;

    for (let right = 0; right < numbers.length; right++) {
        // 1. Grow: the new item joins the window.
        windowSum = windowSum + numbers[right];

        // 2. Shrink while the window breaks the rule.
        while (windowSum > limit) {
            windowSum = windowSum - numbers[left];
            left++;
        }

        // 3. The window is fine now. Is it the longest so far?
        const windowLength = right - left + 1;
        best = Math.max(best, windowLength);
    }

    return best;
}

console.log(longestWithSumAtMost([2, 1, 5, 1, 3, 2], 7)); // 3
```

| right | Item in | Sum after adding | Shrink | Window | Length | best |
| --- | --- | --- | --- | --- | --- | --- |
| 0 | 2 | 2 | no | `[2]` | 1 | 1 |
| 1 | 1 | 3 | no | `[2, 1]` | 2 | 2 |
| 2 | 5 | 8 | drop 2 → sum 6 | `[1, 5]` | 2 | 2 |
| 3 | 1 | 7 | no | `[1, 5, 1]` | 3 | 3 |
| 4 | 3 | 10 | drop 1 → 9, drop 5 → 4 | `[1, 3]` | 2 | 3 |
| 5 | 2 | 6 | no | `[1, 3, 2]` | 3 | 3 |

At `right = 4` the window had to shrink **twice**. That is why step 2 is a `while`, not an `if`.

**Time:** O(n) · **Space:** O(1). There is a loop inside a loop, but `left` only moves forward and never passes the end. Over the whole run, `right` moves n times and `left` moves at most n times: about 2n steps in total.

For the **shortest** window, flip steps 2 and 3: **while the window follows the rule**, record its length, then shrink to try for a shorter one. Minimum Window Substring below works this way.

| You want the... | The inner `while` runs when... | Update the answer... |
| --- | --- | --- |
| Longest window | the window **breaks** the rule | after the `while` |
| Shortest window | the window **follows** the rule | inside the `while`, before you shrink |

### When a window doesn't work

A window only works when **growing it can only push you one way, and shrinking it pulls you back**. With positive numbers, adding an item always makes the sum bigger, so "too big → shrink" is always right.

With **negative numbers**, adding an item can make the sum smaller. Then you can't tell which pointer to move. For sums with negative numbers, like "Subarray Sum Equals K", use a [prefix sum with a hash map](../arrays-hashing/prefix-sum.mdx).

## Classic problems

### 1. Best Time to Buy and Sell Stock

**Problem:** `prices[i]` is a stock's price on day `i`. Buy on one day and sell on a **later** day. Return the best profit, or 0 if you can't make any. `[7, 1, 5, 3, 6, 4]` gives 5: buy at 1, sell at 6.

**Idea:** the window is "buy day to sell day". `right` is the sell day and walks forward one day at a time. Each day, check the profit if we sell today. If today's price is **lower** than the buy day's price, today is a better day to buy, so the window starts again from here.

```js
function maxProfit(prices) {
    let buyDay = 0;
    let bestProfit = 0;

    for (let sellDay = 1; sellDay < prices.length; sellDay++) {
        const profit = prices[sellDay] - prices[buyDay];

        if (profit > bestProfit) {
            bestProfit = profit;
        }

        // A cheaper day to buy? Start the window from here.
        if (prices[sellDay] < prices[buyDay]) {
            buyDay = sellDay;
        }
    }

    return bestProfit;
}

console.log(maxProfit([7, 1, 5, 3, 6, 4])); // 5
console.log(maxProfit([7, 6, 4, 3, 1])); // 0
```

| sellDay | Price | buyDay (price) | Profit | bestProfit | Cheaper than buy day? |
| --- | --- | --- | --- | --- | --- |
| 1 | 1 | 0 (7) | -6 | 0 | yes: `buyDay = 1` |
| 2 | 5 | 1 (1) | 4 | 4 | no |
| 3 | 3 | 1 (1) | 2 | 4 | no |
| 4 | 6 | 1 (1) | **5** | 5 | no |
| 5 | 4 | 1 (1) | 3 | 5 | no |

**Time:** O(n) · **Space:** O(1). One pass over the prices, keeping two numbers.

### 2. Longest Substring Without Repeating Characters

**Problem:** find the length of the longest substring with no repeated character. `"abcabcbb"` gives 3 (`"abc"`), `"bbbbb"` gives 1, and `"pwwkew"` gives 3 (`"wke"`).

**Idea:** keep a **Set** of the characters inside the window. Grow `right` one character at a time. If the new character is **already in the window**, shrink from the left until its old copy is gone. Then add it and measure.

```js
function lengthOfLongestSubstring(text) {
    // The characters inside the window right now.
    const inWindow = new Set();
    let left = 0;
    let best = 0;

    for (let right = 0; right < text.length; right++) {
        const char = text[right];

        // A repeat: shrink from the left until the old copy is gone.
        while (inWindow.has(char)) {
            inWindow.delete(text[left]);
            left++;
        }

        inWindow.add(char);

        const windowLength = right - left + 1;
        best = Math.max(best, windowLength);
    }

    return best;
}

console.log(lengthOfLongestSubstring("abcabcbb")); // 3
console.log(lengthOfLongestSubstring("bbbbb")); // 1
console.log(lengthOfLongestSubstring("pwwkew")); // 3
```

How it runs on `"pwwkew"`:

| right | Char | Repeat? | Shrink | Window | Length | best |
| --- | --- | --- | --- | --- | --- | --- |
| 0 | p | no | | `p` | 1 | 1 |
| 1 | w | no | | `pw` | 2 | 2 |
| 2 | w | yes | drop p, drop w | `w` | 1 | 2 |
| 3 | k | no | | `wk` | 2 | 2 |
| 4 | e | no | | `wke` | 3 | 3 |
| 5 | w | yes | drop w | `kew` | 3 | 3 |

**Time:** O(n) · **Space:** O(min(n, m)), where m is the number of different characters that can appear. Each character is added once and removed at most once. The Set holds at most one copy of each character.

### 3. Minimum Window Substring (Hard)

**Problem:** given `text` and `pattern`, find the **shortest** substring of `text` that contains every character of `pattern`, including repeats. Return `""` if there is none. `text = "ADOBECODEBANC"` and `pattern = "ABC"` give `"BANC"`.

This is the "shortest window" shape. We need two things to know if the window is good:

- **`need`**: a Map that says how many more of each pattern character the window needs. At the start it is the pattern's counts: `A → 1, B → 1, C → 1`. When it goes **below 0**, the window has extra copies.
- **`missing`**: how many pattern characters are still missing in total. At the start it is `pattern.length`, so 3. When `missing` is 0, the window holds everything.

The plan:

1. Count the pattern into `need`.
2. Move `right` one step. If the new character was still needed (`need` above 0), one fewer is missing.
3. **While nothing is missing**, the window is good: record it if it is the shortest so far, then drop the left character. If that character's `need` goes back above 0, it is missing again.

**Step 1: count the characters.**

```js
function countChars(text) {
    const counts = new Map();

    for (const char of text) {
        // get() gives undefined the first time, so start from 0.
        const oldCount = counts.get(char) || 0;
        counts.set(char, oldCount + 1);
    }

    return counts;
}

console.log(countChars("ABC")); // Map(3) { 'A' => 1, 'B' => 1, 'C' => 1 }
```

**Step 2: what happens when a character comes in, and when one goes out.** Both helpers update a `tracker` object that holds `need` and `missing`.

```js
// The right edge moved: one more character is inside the window.
function addChar(tracker, char) {
    if (!tracker.need.has(char)) {
        return;
    }

    // Still needed? Then one fewer is missing.
    if (tracker.need.get(char) > 0) {
        tracker.missing--;
    }

    // Below 0 means "the window has extra copies".
    tracker.need.set(char, tracker.need.get(char) - 1);
}
```

```js
// The left edge moved: one character left the window.
function removeChar(tracker, char) {
    if (!tracker.need.has(char)) {
        return;
    }

    tracker.need.set(char, tracker.need.get(char) + 1);

    // Back above 0? Then the window is missing it again.
    if (tracker.need.get(char) > 0) {
        tracker.missing++;
    }
}
```

**Step 3: slide the window.**

```js
function minWindow(text, pattern) {
    // An empty pattern is never "missing" anything, so the shrink loop
    // below would never stop. Answer it straight away.
    if (pattern.length === 0) {
        return "";
    }

    const tracker = {
        need: countChars(pattern),
        missing: pattern.length,
    };

    let left = 0;
    let bestStart = 0;
    let bestLength = Infinity;

    for (let right = 0; right < text.length; right++) {
        addChar(tracker, text[right]);

        // Nothing is missing: record the window, then shrink it.
        while (tracker.missing === 0) {
            const windowLength = right - left + 1;

            if (windowLength < bestLength) {
                bestStart = left;
                bestLength = windowLength;
            }

            removeChar(tracker, text[left]);
            left++;
        }
    }

    if (bestLength === Infinity) {
        return "";
    }

    return text.slice(bestStart, bestStart + bestLength);
}
```

**Step 4: try it.**

```js
console.log(minWindow("ADOBECODEBANC", "ABC")); // BANC

// "AA" needs two A's, but the text has only one.
console.log(minWindow("A", "AA") === ""); // true
```

The key moments on `"ADOBECODEBANC"`:

| `right` reaches | Window when it becomes good | While shrinking | Shortest so far |
| --- | --- | --- | --- |
| 5 (`C`) | `ADOBEC` | record `ADOBEC` (6), drop `A` → A is missing | `ADOBEC` |
| 10 (`A`) | `DOBECODEBA` | drop `D`, `O`, `B` (a second B is still inside), `E`: still good but not shorter than 6; drop `C` → C is missing | `ADOBEC` |
| 12 (`C`) | `ODEBANC` | drop `O`, `D`, record `EBANC` (5), drop `E`, record `BANC` (4), drop `B` → B is missing | `BANC` |

We save only `bestStart` and `bestLength` and slice **once** at the end. Slicing at every step would add a hidden O(n) copy each time.

**Time:** O(n + m), where n is the text length and m the pattern length. Counting the pattern is O(m). Then `right` moves n times and `left` at most n times, and each step is O(1). **Space:** O(m) for the `need` Map.

### 4. Permutation in String

**Problem:** does `text` contain some reordering of `pattern` (an anagram of it) as a substring? Both hold only lowercase letters. `pattern = "ab"` and `text = "eidbaooo"` give `true`: `"ba"` is inside. `"ab"` and `"eidboaoo"` give `false`.

**Idea:** an anagram of `pattern` has exactly `pattern.length` letters, so this is a **fixed-size window**. Keep the letter counts of the window in an array of 26 (slot 0 is `"a"`). Slide it one letter at a time: add the letter coming in, remove the letter going out, and compare the counts with the pattern's counts.

**Step 1: compare two arrays of 26 counts.**

```js
function sameCounts(countsA, countsB) {
    for (let i = 0; i < 26; i++) {
        if (countsA[i] !== countsB[i]) {
            return false;
        }
    }

    return true;
}
```

**Step 2: slide the window.**

```js
function containsAnagram(pattern, text) {
    const size = pattern.length;

    if (size > text.length) {
        return false;
    }

    // Letter counts: slot 0 is "a", slot 25 is "z".
    const patternCounts = new Array(26).fill(0);
    const windowCounts = new Array(26).fill(0);

    // The pattern, and the first window: the first `size` letters of text.
    for (let i = 0; i < size; i++) {
        const patternPlace = pattern.charCodeAt(i) - 97;
        patternCounts[patternPlace]++;

        const textPlace = text.charCodeAt(i) - 97;
        windowCounts[textPlace]++;
    }

    if (sameCounts(patternCounts, windowCounts)) {
        return true;
    }

    // Slide: one letter comes in on the right, one goes out on the left.
    for (let right = size; right < text.length; right++) {
        const comingIn = text.charCodeAt(right) - 97;
        const goingOut = text.charCodeAt(right - size) - 97;

        windowCounts[comingIn]++;
        windowCounts[goingOut]--;

        if (sameCounts(patternCounts, windowCounts)) {
            return true;
        }
    }

    return false;
}

console.log(containsAnagram("ab", "eidbaooo")); // true
console.log(containsAnagram("ab", "eidboaoo")); // false
```

**Time:** O(n + m), where n is the text length and m the pattern length. Each slide is O(1) work plus one compare of 26 slots, and 26 is a constant. **Space:** O(1): two arrays of 26, whatever the input size.

**Find All Anagrams in a String** is the same loop. Instead of returning `true` on a match, save the window's start, `right - size + 1` (or 0 for the first window), and return the list at the end.

## How to spot it

- The answer is a **subarray or substring**: items **in a row**, "contiguous", "consecutive".
- The question says **longest**, **shortest**, **maximum sum**, **at most K**, **at least K**, or **contains all of**.
- "**Of size k**" or "every k items in a row": a fixed-size window.
- For sums: the numbers are **never negative**.
- Not a window: "**subsequence**" (items don't have to be next to each other) usually means [dynamic programming](../dynamic-programming/dp-basics.mdx). An exact sum with **negative numbers** means [prefix sum](../arrays-hashing/prefix-sum.mdx).

## Common mistakes

- **Length as `right - left`.** It's `right - left + 1`: a window from 2 to 2 holds one item.
- **`if` instead of `while` when shrinking.** One step back may not be enough, like at `right = 4` in the sum example.
- **Updating the answer before the window is fixed** (in a "longest" problem). Measure after the `while`.
- **Moving `left` without removing its item** from the sum, Set or Map. The window then holds items that aren't in it.
- **Using a window with negative numbers** for a sum. Use a prefix sum.
- **Slicing the window at every step.** `text.slice(left, right + 1)` inside the loop is a hidden O(n) copy. Keep the start and length, and slice once at the end.

## In the interview

Say why it's a window and why it's O(n):

> "Substrings are contiguous, so I'll use a sliding window. `right` adds one character at a time. When the window has a repeat, I move `left` forward until it doesn't. Each character enters the window once and leaves at most once, so it's O(n) time. The Set holds at most one copy of each character."

**Likely follow-up:** "Can you skip shrinking one step at a time?"

**Answer:** "Yes. I keep a Map from each character to the last index where I saw it. On a repeat, I jump `left` straight to one past that index, but never backward: `left = Math.max(left, lastIndex + 1)`. It's still O(n), but `left` jumps instead of walking."

<Callout title="Remember this" type="success">
  - A window is the items **from `left` to `right`**, both included. Its length is **`right - left + 1`**.
  - **Fixed size:** add the item coming in, subtract the item going out. O(n) instead of O(n · k).
  - **Anagram of a pattern inside a text:** a fixed window of `pattern.length`, with two arrays of 26 letter counts.
  - **Variable size:** grow with `right` every step, and shrink with `left` **while** the rule is broken.
  - `left` only moves forward, so the loop inside a loop is still **O(n)**.
  - **Longest** → measure after shrinking. **Shortest** → measure while the window is good, then shrink.
  - Sum windows need **non-negative numbers**. With negatives, use a prefix sum and a hash map.
</Callout>
