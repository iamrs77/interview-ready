## Guide

**[How to Solve a Problem in an Interview](./interview-framework.mdx)**

- **7 steps:** Understand → Examples → Brute force → Better way → Code → Test by hand → Complexity.
- **Ask before you code:** sorted? negatives? duplicates? always an answer? how big?
- **Say the brute force first,** with its Big O. Then find the work that repeats, and pick a pattern that removes it.
- Two Sum: a **Map** of "number → index" turns the inner loop into an O(1) lookup: O(n²) becomes O(n).
- **Test with a trace table** on a normal case and a trap case before you say "done".
- **Always say time and space,** with a one-line reason each. Talk the whole time.

## 1. Foundations

**[Big O Notation](./foundations/big-o.mdx)**

- **Big O = how the work grows** as the input grows, not seconds. Always say **time and space**.
- Fastest to slowest: **O(1), O(log n), O(n), O(n log n), O(n²), O(2ⁿ), O(n!)**.
- **Drop the constants, keep the biggest term.** One loop after another: **add**. One inside another: **multiply**.
- Watch for **hidden loops**: `includes`, `indexOf`, `shift`, `slice`, `splice` are O(n). `Map` and `Set` lookups are O(1) on average.
- **Cutting in half each step = O(log n).** Sorting = O(n log n).
- `push` is **amortized O(1)**: a big copy once in a while, cheap on average.

**[How Arrays Work in Memory](./foundations/how-memory-works.mdx)**

- **Memory is a row of numbered boxes.** An array is one unbroken block of same-size boxes.
- **`arr[i]` is O(1):** address = start + i × size. One sum, no searching.
- **Insert or remove at the front or middle is O(n):** every item after it shifts. At the end (`push`, `pop`) it is O(1).
- **A full dynamic array doubles and copies everything.** The big copies are rare, so `push` is **amortized O(1)**.
- **Strings are arrays of character codes** (`"a"` is 97). They can't change; every edit builds a new string.
- Taking from the front a lot? Use a **head index**, not `shift()`.

**[Recursion](./foundations/recursion.mdx)**

- **Recursion = a function calling itself on a smaller input.** It needs a **base case** (stop) and a **recursive case** (smaller step).
- Three questions: what is the smallest case? How do I shrink the input? How do I use the smaller answer?
- Each waiting call sits on the **call stack**, so recursion uses **O(depth) space**.
- **No base case, or too deep → stack overflow** (`Maximum call stack size exceeded`). Node's limit is around 10,000 calls.
- Plain Fibonacci repeats work (`fib(2)` three times inside `fib(5)`): O(2ⁿ). **Remember the answers → DP.**
- Trees, nested data, "all combinations" → recursion. Simple walks → a loop.

## 2. JavaScript Toolkit

**[Strings in JavaScript](./js-toolkit/strings.mdx)**

- Strings **can't be changed**. Every method returns a **new** string, so save the result.
- `s[i]` and `s.length` are **O(1)**. `includes`, `indexOf`, `slice` and `split` are hidden loops: **O(n)**.
- Build big strings with an **array + `join("")`**, not `+=` in a loop.
- `"a"` is 97 and `"A"` is 65: `char.charCodeAt(0) - 97` turns a letter into a slot from 0 to 25.
- `replace` changes only the **first** match, and `split(" ")` can give empty strings.
- Strings compare **character by character**: `"10" < "9"` is `true`.

**[Arrays in JavaScript](./js-toolkit/arrays.mdx)**

- `push` and `pop` are **O(1)**. `shift`, `unshift` and `splice` are **O(n)**: every other item moves.
- `includes`, `indexOf` and `find` are hidden loops: **O(n)**. Many lookups? Use a Set.
- `sort()` sorts as **text**: pass `(a, b) => a - b` for numbers. It's O(n log n) and changes the array.
- `sort`, `reverse`, `splice` and `fill` **change the original**; `slice`, `map`, `filter` and `toSorted` return a new array.
- Build a grid with a loop or `Array.from`, never `new Array(n).fill([])`: that's one shared row.

**[Objects, Maps and Sets](./js-toolkit/objects-maps-sets.mdx)**

- Object, Map and Set find a key in **O(1) on average**. Array `includes` is O(n).
- **Object keys are always strings**: `obj[1]` is `obj["1"]`, and `Object.keys` gives strings.
- Pick a **Map** for counting and lookups: any key type, keeps the **order you added**, has `size`, no built-in keys like `"toString"`.
- Use `map.get` and `map.set`, never `map[key]`. `forEach` gives the **value first**, then the key.
- `[...new Set(arr)]` removes duplicates in O(n).
- Arrays as Map or Set keys are matched **by reference**: use a string key like `"2,3"`.

**[Numbers and Math](./js-toolkit/numbers-and-math.mdx)**

- `/` gives decimals: `Math.floor(7 / 2)` is 3. For negatives, `Math.floor` goes **down** (-4), `Math.trunc` goes **toward 0** (-3).
- `%` keeps the sign: `-7 % 3` is -1. Check odd with `% 2 !== 0`.
- Start a minimum at `Infinity` and a maximum at `-Infinity`, never at 0.
- `0.1 + 0.2 !== 0.3`: compare decimals with a small gap. `toFixed` returns a **string**.
- Whole numbers are exact only up to `Number.MAX_SAFE_INTEGER` (about 9 × 10¹⁵). Bigger: **BigInt**.
- Digit loops (`% 10`, then `Math.floor(number / 10)`) are **O(log n)**: one step per digit.

## 3. Arrays and Hashing

**[Arrays and Strings](./arrays-hashing/arrays-and-strings.mdx)**

- Indexes go from **0 to `length - 1`**. Most array bugs are off by one at the ends.
- **In place** = change the input with a few variables: O(1) extra space. Ask first if you may.
- **Swap** and **reverse a range** (two pointers) are the main in-place tools.
- **Rotate right by k:** take `k % length`, reverse all, reverse the first k, reverse the rest.
- Strings can't be changed: **split → change → join**. Build long strings with an **array + `join("")`**.
- To pack a list of strings into one, write **length + `#` + word**.

**[Hash Maps and Sets](./arrays-hashing/hash-maps-and-sets.mdx)**

- A hash map finds a key in **O(1) on average**; a set answers "seen it?" in O(1). The price is **O(n) extra memory**.
- Four jobs: **seen before** (Set), **counting** (item → count), **where** (value → index), **grouping** (key → list).
- Two Sum: `needed = target - number`. **Check the Map before you store** the number.
- Anagrams have the **same counts**, and the same **sorted letters**. Sorted letters make a good group key.
- Top K: count, then sort (O(n log n)) or **bucket by count** (O(n)).
- Longest Consecutive Sequence: a Set; only count up from numbers whose `number - 1` is missing. O(n).
- Valid Sudoku: one Set per row, column and box. Box number = `Math.floor(row / 3) * 3 + Math.floor(col / 3)`.
- Start counts from 0: `counts.get(item) || 0`.

**[Prefix Sum](./arrays-hashing/prefix-sum.mdx)**

- `prefix[i]` = the sum of the **first i numbers**, and `prefix[0] = 0`. Build it once in O(n).
- The sum from `left` to `right` = **`prefix[right + 1] - prefix[left]`**: O(1).
- **Subarray Sum Equals K:** running sum + a Map of sums seen. Look up `runningSum - k`. Start with `0 → 1`.
- Longest instead of count: store each sum's **first index** (start with `0 → -1`). Divisible by k: store the remainder, made positive.
- Prefix sums work with **negative numbers**; a sliding window doesn't.
- **Product except self:** products from the left × products from the right. Start at 1, no division.

## 4. Two Pointers and Sliding Window

**[Two Pointers](./two-pointers/two-pointers.mdx)**

- A **pointer is a variable that holds an index**. Read the value with `numbers[left]`.
- **Opposite ends** need sorted data: sum too small → `left++`, too big → `right--`. O(n) time, O(1) space.
- **Slow writer, fast reader** changes an array in place: `slow` is where the next kept item goes.
- Loop **while `left < right`**, and move at least one pointer on every pass.
- **3Sum = sort + fix the first number + two pointers.** O(n²). Skip copies to avoid repeat triplets.
- Container With Most Water: **move the shorter wall**.
- Trapping Rain Water: water on a bar = **the lower of the tallest left and tallest right**, minus its height. Work on the side whose tallest is lower.

**[Sliding Window](./two-pointers/sliding-window.mdx)**

- A window is the items **from `left` to `right`**, both included. Its length is **`right - left + 1`**.
- **Fixed size:** add the item coming in, subtract the item going out. O(n) instead of O(n · k).
- **Anagram of a pattern inside a text:** a fixed window of `pattern.length`, with two arrays of 26 letter counts.
- **Variable size:** grow with `right` every step, and shrink with `left` **while** the rule is broken.
- **At most k changes:** a window is fine while `length - mostCommonCount <= k`.
- `left` only moves forward, so the loop inside a loop is still **O(n)**.
- **Longest** → measure after shrinking. **Shortest** → measure while the window is good, then shrink.
- Sum windows need **non-negative numbers**. With negatives, use a prefix sum and a hash map.

## 5. Binary Search and Sorting

**[Binary Search](./searching-sorting/binary-search.mdx)**

- **Binary search = check the middle, throw away half.** It needs sorted data (or a yes/no check that flips only once). 1,000,000 items → about 20 checks.
- **The template:** `right = length - 1`, `while (left <= right)`, then `left = mid + 1` or `right = mid - 1`.
- `mid = left + Math.floor((right - left) / 2)`: **floor** for a whole index, and the `left +` form never overflows.
- For **first / last / insert position**, save `answer = mid` and keep searching.
- **Rotated array:** one half is always sorted. Check if the target is inside that half.
- **"Smallest speed / capacity that works"** → binary search on the answer, with a small check function.

**[Sorting](./searching-sorting/sorting.mdx)**

- **Good sorts are O(n log n):** about log n levels of halving, with n work on each level. Simple sorts are O(n²).
- **Merge sort:** split in half, sort each half, merge with two pointers. Always O(n log n), O(n) space, stable.
- **Quick sort:** pick a pivot, put smaller items left and bigger items right, repeat. O(n log n) usually, **O(n²) worst**; a random pivot fixes it, and a **three-way split** handles many equal items.
- In JavaScript: **`sort((a, b) => a - b)`** for numbers. Negative means `a` first. It changes the array and is stable.
- **Sort first** when the order doesn't matter: neighbors, two pointers, intervals, binary search. Always count the O(n log n).

## 6. Stacks and Queues

**[Stacks](./stacks-queues/stacks.mdx)**

- **Stack = Last In, First Out.** Add and remove at the top only, like a stack of plates.
- In JavaScript, use an **array**: `push`, `pop` and `stack[stack.length - 1]` to peek. All O(1). Never `shift` or `unshift`.
- `pop()` on an empty array gives back **`undefined`**, with no error.
- **Valid Parentheses:** push openers, pop on each closer and check it matches, and the stack must be **empty** at the end.
- **Min Stack:** a second stack holds "the smallest so far" for every level.
- **Reverse Polish Notation:** numbers wait on the stack. The **first pop is the right** number.

**[Monotonic Stack](./stacks-queues/monotonic-stack.mdx)**

- **Monotonic stack = a stack kept in order.** Before pushing, pop everything that would break the order.
- **Next greater:** pop while the top is smaller. Each popped item's answer is the current item.
- Store **indexes**, not values: you need the position to write the answer and to measure distances.
- It's **O(n)**: every index is pushed once and popped at most once, even with a `while` inside the `for`.
- **Daily Temperatures:** answer = today's index minus the popped day's index.
- **Histogram:** for each bar, find the nearest shorter bar on both sides; `width = right - left - 1`.

**[Queues and Deques](./stacks-queues/queues-and-deques.mdx)**

- **Queue = First In, First Out:** join at the back, leave from the front. A **deque** is open at both ends.
- **`shift()` is O(n):** every other item moves. Emptying a queue with it is O(n²).
- **A fast queue in JavaScript:** an array plus a **head index** (dequeue = read `items[head]`, then `head++`), or a linked list.
- **BFS uses a queue:** it visits in rings, so the first time you reach something is by the fewest steps.
- **Sliding Window Maximum:** a deque of indexes with values going down. Drop old ones from the front, smaller ones from the back; the front is the max. O(n).
- **Queue from two stacks:** pour `inbox` into `outbox` only when `outbox` is empty.

## 7. Linked Lists

**[Linked Lists](./linked-lists/linked-lists.mdx)**

- A node is `{ val, next }`. `head` is the first node; the last node's `next` is `null`.
- Walk with `current = current.next`. Reading position i is **O(n)**; adding at the front is **O(1)**.
- Doubly linked nodes point at each other, so the console prints `[Circular *1]`. It's not an error.
- **Dummy node:** a fake node before the head removes the head special case. Return `dummy.next`.
- **Reverse:** save next, turn the arrow, move prev, move current. O(n) time, O(1) space.
- Always check `!== null` before reading `.next` or `.val`.

**[Fast and Slow Pointers](./linked-lists/fast-slow-pointers.mdx)**

- `slow` moves 1, `fast` moves 2. Loop while `fast !== null && fast.next !== null`.
- When `fast` reaches the end, `slow` is in the **middle** (the second middle for even lengths; start `fast` at `head.next` for the first).
- **Cycle:** if `slow === fast` (the same node), there's a loop. O(n) time, O(1) space, instead of a Set's O(n).
- **Nth from the end:** give `fast` an n-node head start, then move both together. A dummy node handles removing the head.
- **Reorder List / Palindrome:** find the middle, reverse the second half, then walk both halves.

## 8. Trees

**[Tree Basics](./trees/tree-basics.mdx)**

- A tree node in JavaScript is `{ val, left, right }`. A missing child is `null`, so **check for `null` before reading a child**.
- **Depth** counts edges down from the root (root = 0). **Height** counts edges up from the leaves (leaf = 0). LeetCode's "max depth" counts **nodes**.
- **Full:** 0 or 2 children. **Complete:** filled level by level from the left (heaps). **Balanced:** left and right heights differ by at most 1 at **every** node.
- Tree operations cost **O(h)**: about **log n** when balanced, **n** when the tree is a chain.
- Recursion on a tree uses **O(h) stack space**.
- Two ways to walk a tree: **DFS** (recursion or a stack) and **BFS** (level by level with a queue).

**[Binary Trees and DFS](./trees/binary-trees.mdx)**

- **Preorder** = node, left, right. **Inorder** = left, node, right (sorted on a BST). **Postorder** = left, right, node.
- For any tree problem, decide **what one call returns** for its subtree, what it returns for `null`, and how to build it from the two children's answers. Then **trust the calls**.
- Answers go **up** through return values (height, size) or **down** through arguments (remaining sum, depth so far).
- When the parent needs something different from the final answer (Diameter, Max Path Sum), **return what the parent needs** and track the answer in an outer variable.
- **Serialize** = preorder with `#` for every empty spot. **Deserialize** reads it back in the same order with one index.
- Iterative inorder: **go left and push, pop and visit, then go right**.
- Tree DFS is **O(n) time** and **O(h) space**: O(log n) if balanced, O(n) for a chain.

**[Tree BFS](./trees/tree-bfs.mdx)**

- **BFS = level by level, with a queue.** Take from the front, add children to the back.
- The level template: **save `levelSize = queue.length` first**, then take out exactly that many nodes.
- Right side view = **the last node of each level** (it can be a left child).
- Minimum depth: BFS **stops at the first leaf**. With DFS, a missing child is not a leaf.
- BFS is O(n) time and **O(w) space** (widest level). DFS is O(h) space.
- `shift()` is O(n). For big trees, keep a **`front` index** instead.

**[Binary Search Trees](./trees/binary-search-trees.mdx)**

- **BST rule:** everything in the left subtree is smaller, everything in the right subtree is bigger, at **every** node.
- **Inorder of a BST is sorted.** Kth smallest = stop the inorder walk at the k-th node.
- Search, insert, min and max walk **one path**: O(h). That's O(log n) only if the tree is balanced.
- **Validate:** pass an allowed range (`low`, `high`) down. Going left, `high` becomes the node's value; going right, `low` does.
- **LCA in a BST:** both smaller, go left; both bigger, go right; otherwise this node is the answer.
- Min = go left until you can't. Max = go right until you can't.
- **Delete:** a leaf is removed; one child takes the node's place; two children → copy in the smallest value from the right subtree, then delete that one.

**[Tries](./trees/tries.mdx)**

- **Trie = a tree of letters.** Words with the same start share the same path.
- A node is `{ children: {}, isEnd: false }`. **`isEnd` marks where a word ends.**
- Insert, search and startsWith are all **O(L)**, the length of the word, not the number of words.
- **search** needs the path **and** `isEnd`. **startsWith** only needs the path.
- Wildcard `.`: **try every child** with DFS, and return `false` only after all of them fail.
- Use a trie for **prefixes**. For exact lookups only, a `Set` is simpler.

## 9. Heaps

**[Heaps and Priority Queues](./heaps/heaps.mdx)**

- A heap gives the smallest (min-heap) or biggest (max-heap) item in **O(1)**; `push` and `pop` are **O(log n)**.
- It lives in an array: children at `2i + 1` and `2i + 2`, parent at `Math.floor((i - 1) / 2)`.
- **push** = add at the end, bubble up. **pop** = take the top, move the last item to the top, bubble down (swap with the **smaller** child).
- Only `heap[0]` is in order; the rest of the array is **not sorted**.
- **Max-heap:** flip the comparisons, push negative numbers, or pass a compare function.
- **JavaScript has no built-in heap:** be ready to write one, or ask to assume one.

**[Top K and Merge K](./heaps/top-k.mdx)**

- **k largest → min-heap of size k. k smallest or closest → max-heap of size k.** The top is the item you'd throw out next.
- Push, then pop when `size() > k`. **O(n log k)** time, **O(k)** space.
- **Top K Frequent:** count with a Map, then a heap by count, or **bucket sort** for O(n).
- **Merge K sorted:** a heap of the k front items. Pop the smallest, push the next one from the same list. **O(N log k)**.
- **Median of a stream:** max-heap for the small half, min-heap for the big half; sizes equal, or small has one more.
- JavaScript has no heap: write a `Heap` with a compare function, or ask to assume one.

## 10. Graphs

**[Graph Basics](./graphs/graph-basics.mdx)**

- **Graph = nodes + edges.** Edges can be two-way (undirected) or one-way (directed), and can carry a weight.
- Use an **adjacency list**: `graph[node]` is the list of its neighbors. O(V + E) memory. A matrix is O(V²).
- Build from an edge list: one empty list per node, then push each edge, **both ways if undirected**.
- Never `new Array(n).fill([])`: all slots share one array. Use a loop or `Array.from({ length: n }, () => [])`.
- **A grid is a graph:** cells are nodes, a `directions` array gives the 4 neighbors, and you always check the bounds.
- Ask first: directed? weighted? cycles? separate pieces? labels from 0 or from 1?

**[Graph BFS and DFS](./graphs/graph-bfs-dfs.mdx)**

- **DFS** goes deep (recursion or a stack). **BFS** goes ring by ring (a queue). Both need a **visited** set and cost **O(V + E)**.
- The BFS queue is an array plus a **head index**. `shift()` is O(n) and makes BFS O(V²).
- In BFS, **mark visited when you add** a node to the queue, not when you take it out.
- **Fewest steps** with equal-cost edges → BFS. Many starting points → put them **all in the queue at once** (Rotting Oranges).
- States instead of nodes (Word Ladder): **make the neighbors on the spot**, and delete a word from the Set when it joins the queue.
- Count groups (islands): loop over every node; each unvisited one starts a new search and is a new group.
- Cycles: undirected → **skip the parent**. Directed → **three states**; a loop is an arrow to a node that is still `VISITING`.

**[Topological Sort](./graphs/topological-sort.mdx)**

- **Topological sort = an order where every task comes after the tasks it needs.** Only possible with **no loops** (a DAG).
- **In-degree** = how many tasks a node still waits for. **In-degree 0 = ready.**
- **Kahn's algorithm:** queue every in-degree-0 node; take one, lower its neighbors' in-degree, and add any that reach 0.
- **Loop check:** if the order has fewer than n nodes, there is a loop (Course Schedule → `false`).
- `[a, b]` = "a needs b" means the arrow is **b → a**. Get the direction right.
- O(V + E) time and space. Many valid orders can exist.

**[Union-Find](./graphs/union-find.mdx)**

- **Union-Find = groups with a leader.** `parent[i]` points up; a **root points to itself**.
- **find(x)** follows parents up to the root. **union(a, b)** links one **root** under the other.
- Same group means **`find(a) === find(b)`**. Never compare `parent[a]` with `parent[b]`.
- **Path compression** (point straight at the root) + **union by size** (small under big) → **almost O(1)** per operation.
- `union` returning **false** means "already connected": that edge closes a loop (Redundant Connection).
- Count groups: start at n, and subtract 1 for every union that returns `true`.
- **Kruskal (cheapest way to connect everything):** sort the edges cheapest first, and keep an edge only when `union` returns `true`.

**[Shortest Paths](./graphs/shortest-paths.mdx)**

- **Different edge costs → Dijkstra.** All the same cost → **BFS** (simpler, O(V + E)).
- Dijkstra: `dist` starts at Infinity (the start is 0), plus a **min-heap of [distance, node]**. Pop the closest, **skip old pairs**, relax its edges.
- **Relax** = if `dist[node] + weight` is less than `dist[neighbor]`, save the cheaper cost and push it.
- A node is final when it **comes out** of the heap, not when it goes in.
- O(E log V) time. **No negative weights** (that's Bellman-Ford).
- **At most k stops** → Bellman-Ford: `k + 1` rounds over every edge, each round reading a **copy** of the last round's prices.
- Network Delay Time = the **largest** shortest distance; any Infinity → -1.

## 11. Backtracking

**[Backtracking](./backtracking/backtracking.mdx)**

- **Backtracking = choose, explore, undo.** One recursive call per choice; undo it before trying the next.
- Save **a copy**: `result.push([...path])`. Saving `path` itself saves one shared array that ends up empty.
- `backtrack(i + 1)` → each item once (subsets, combinations). `backtrack(i)` → reuse (combination sum). Loop from 0 with `used` → order matters (permutations).
- Duplicates: **sort**, then skip `nums[i] === nums[i - 1]` when `i > start`. For permutations, skip it when `nums[i - 1]` is still unused.
- Cost = number of answers × cost to copy one: subsets O(n · 2ⁿ), permutations O(n · n!).
- "Return all ..." with a small n → backtracking. "How many ways" or "the best" → think DP.

**[Backtracking on Grids](./backtracking/grid-backtracking.mdx)**

- Grid backtracking: from a cell, **choose** a neighbour, **explore**, **undo**. Check the bounds first, then the cell.
- Mark a used cell (`board[row][col] = "#"`) and **always put it back** before returning.
- Word Search: O(rows × cols × 3^L) time, O(L) space.
- N-Queens: one queen per row; Sets for used columns, `row - col` and `row + col`. O(n!) time.
- **Pruning** = stop a path as soon as it can't work (attacked cell, wrong letter, sorted and too big). Same answers, far fewer calls.
- Cells stay visited for good, with no undo? That's plain DFS or flood fill, not backtracking.

## 12. Dynamic Programming

**[Dynamic Programming Basics](./dynamic-programming/dp-basics.mdx)**

- **DP = solve each small problem once and reuse the answer.** It needs repeated subproblems and a big answer built from smaller ones.
- The recipe: **1. what `dp[i]` means, 2. the recurrence, 3. base cases, 4. order of filling** (and where the answer is).
- **Memoization** = recursion + a notebook (top-down). **Tabulation** = a loop filling an array from small to big (bottom-up).
- Plain Fibonacci is O(2ⁿ). With a memo or a table it's O(n). If `dp[i]` only needs the last two cells, keep **two variables**: O(1) space.
- Signals: **number of ways, min/max, is it possible**, a choice at each step, repeated recursive calls.
- Big O of DP = **number of cells × work per cell**.

**[1D Dynamic Programming](./dynamic-programming/one-d-dp.mdx)**

- 1D DP = **one changing value** (an index or an amount), so the answers fit in one array.
- `dp[i]` means **"best for the first `i` items"** (answer: `dp[n]`) or **"best ending at `i`"** (answer: the biggest cell).
- **House Robber:** `max(skip, rob + dp[i - 2])`. **Coin Change:** `min(dp[i - coin] + 1)`, start with Infinity.
- **Kadane:** `current = max(num, current + num)`. A negative running sum means start fresh. O(n) time, O(1) space.
- **LIS:** O(n²) by looking back at every smaller number; O(n log n) with `tails` + binary search.
- **Word Break:** `dp[end]` is true if `dp[start]` is true and `slice(start, end)` is a word. **Decode Ways:** one digit (1-9) + two digits (10-26).

**[2D Dynamic Programming](./dynamic-programming/two-d-dp.mdx)**

- 2D DP = **two changing values** (row and column, or a position in each of two strings), so the answers fit in a **table**.
- A cell is usually built from **above, left and the diagonal**, so fill **row by row, left to right**.
- Two strings → a `(m + 1) × (n + 1)` table. Row 0 and column 0 are the **empty string**.
- **Unique Paths:** above + left. **LCS:** match → diagonal + 1, else max(above, left). **Edit Distance:** match → diagonal, else 1 + min(above, left, diagonal).
- Make tables with `Array.from({ length: rows }, () => new Array(cols).fill(0))`, never `fill(new Array(...))`.
- Each row only needs the row above → keep **one or two rows** for O(n) space.

**[Knapsack](./dynamic-programming/knapsack.mdx)**

- **0/1 knapsack:** items, a limit, and for each item **skip it or take it**. `dp[i][c] = max(dp[i - 1][c], value + dp[i - 1][c - weight])`.
- Greedy (best value per kg) **fails**. Time is O(n × limit).
- **One row:** loop the limit **down** for 0/1 (each item once), **up** for unbounded (reuse allowed).
- **Partition Equal Subset Sum** = can a subset reach `total / 2`? **Target Sum** = count subsets that reach `(target + total) / 2`.
- Base case by goal: max value → `0`, possible → `true`, count ways → `1`.
- **Coin Change II:** coins in the outer loop counts combinations; amount outside counts orders.

## 13. Greedy and Intervals

**[Greedy](./greedy-intervals/greedy.mdx)**

- **Greedy = take the best choice right now, and never go back.** Usually one loop, O(n), or O(n log n) with a sort.
- Greedy is not always right: coins **[1, 3, 4] for 6** gives 4 + 1 + 1 (3 coins), but 3 + 3 (2 coins) is best. That needs DP.
- **Try to break it** with small inputs first. Then explain it with an **exchange argument**: swapping a best answer's choice for mine never makes it worse.
- **Jump Game:** keep `farthest`; stuck if `i > farthest`. **Jump Game II:** count zones, jump when `i === currentEnd`, loop to `n - 2`.
- **Gas Station:** total gas < total cost → `-1`; if the tank goes negative at `i`, start again at `i + 1`.
- **Kadane:** add the number, update `best`, drop the running sum when it goes below 0. **Partition Labels:** stretch the part to each letter's last index.

**[Intervals](./greedy-intervals/intervals.mdx)**

- An interval is `[start, end]`. **Sort by start first:** `intervals.sort((a, b) => a[0] - b[0])`. Never call `sort()` with no compare function.
- Two intervals overlap when **each starts before the other ends**. After sorting, just check `next[0] <= last[1]`.
- **Merge:** compare with the last merged interval. Gap → add it. Overlap → `last[1] = Math.max(last[1], end)`.
- **Insert:** three parts, no sort: copy the ones before, merge the ones that overlap, copy the ones after. O(n).
- **Remove the fewest:** sort by **end** and keep the one that ends first (greedy).
- **Meeting rooms:** sort starts and ends separately. If a start is at or after the earliest unused end, reuse that room; otherwise open a new one.

## 14. Math and Bits

**[Bit Manipulation](./math-bits/bit-manipulation.mdx)**

- Bit operators work **column by column**: `&` both, `|` either, `^` different. `<<` doubles, `>>` halves.
- In JavaScript, bit operators use **32-bit signed** numbers. `>>>` fills with 0s; `x >>> 0` reads the bits as positive.
- XOR: `x ^ x = 0` and `x ^ 0 = x`, so **pairs cancel**: Single Number, Missing Number.
- `n & (n - 1)` removes the lowest 1 bit: count the 1 bits, Power of Two (with `n > 0`).
- Always use brackets: `(n & 1) === 0`.
- Counting Bits in O(n): `bits[i] = bits[i >> 1] + (i & 1)`.

**[Math and Matrices](./math-bits/math-and-matrices.mdx)**

- A matrix is an array of rows: `matrix[row][col]`. Rows = `matrix.length`, columns = `matrix[0].length`.
- Rotate 90° clockwise in place = **transpose, then reverse each row**. O(n²) time, O(1) space.
- Spiral = four walls; move a wall after each side, and check `top <= bottom` and `left <= right` before the last two sides.
- Set Matrix Zeroes: **find first, change later**.
- Fast power: square the base, halve the exponent → O(log n). Negative exponent: use 1 / base.
- Digits: `% 10` and `Math.floor(number / 10)` on the absolute value. GCD: `gcd(a, b) = gcd(b, a % b)`.
