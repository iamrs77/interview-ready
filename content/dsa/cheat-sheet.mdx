## The interview in 7 steps

Full lesson: [How to Solve a Problem in an Interview](./interview-framework.mdx).

1. **Understand** (about 5 min). Say the problem back. Ask: sorted? negatives? duplicates? always an answer? how big?
2. **Examples** (about 3 min). Write 3 or 4 small inputs with their answers. Include the traps: empty, one item, duplicates, negatives.
3. **Brute force** (about 3 min). Say the simplest idea that works, and its Big O.
4. **Better way** (5 to 10 min). Find the work that repeats. Match the signal to a pattern (table below). Get a yes before you code.
5. **Code** (about 15 min). Small steps, clear names. Talk as you go.
6. **Test by hand** (about 5 min). Trace a normal case and a trap case, line by line.
7. **Complexity** (about 2 min). Say time and space, with a one-line reason each.

**The input size tells you the Big O you need:**

| Input size (n) | Fast enough | Often means |
| --- | --- | --- |
| up to about 20 | O(2ⁿ) | Backtracking: try every choice |
| up to about 1,000 | O(n²) | Two loops are fine |
| up to about 100,000 | O(n log n) or O(n) | Sorting, a hash map, two pointers, a sliding window, a heap |
| more, or "do it in O(log n)" | O(log n) | Binary search |

## Code templates

### Two pointers

Sorted array, one pointer at each end. Each step throws away one number for good. O(n) time, O(1) space.

```js
// Find two numbers in a SORTED array that add up to target.
function twoSumSorted(numbers, target) {
    let left = 0;
    let right = numbers.length - 1;

    while (left < right) {
        const sum = numbers[left] + numbers[right];

        if (sum === target) {
            return [left, right];
        } else if (sum < target) {
            // Too small: we need a bigger number.
            left++;
        } else {
            // Too big: we need a smaller number.
            right--;
        }
    }

    return [];
}
```

### Sliding window

Grow with `right` every step. Shrink with `left` **while** the window breaks the rule. `left` only moves forward, so it's O(n).

```js
// The longest window whose sum is at most limit.
function longestWindow(numbers, limit) {
    let left = 0;
    let windowSum = 0;
    let best = 0;

    for (let right = 0; right < numbers.length; right++) {
        // 1. Grow: the new item joins the window.
        windowSum = windowSum + numbers[right];

        // 2. Shrink while the window breaks the rule.
        while (windowSum > limit) {
            windowSum = windowSum - numbers[left];
            left++;
        }

        // 3. Measure: the window follows the rule again.
        const windowLength = right - left + 1;
        best = Math.max(best, windowLength);
    }

    return best;
}
```

- **Shortest window:** measure **inside** the `while` (while the window is good), then shrink.
- **Fixed size k:** add `numbers[right]`, subtract `numbers[right - k]`.

### Binary search

Check the middle, throw away half. O(log n) time, O(1) space.

```js
function binarySearch(numbers, target) {
    let left = 0;
    let right = numbers.length - 1;

    while (left <= right) {
        const mid = left + Math.floor((right - left) / 2);

        if (numbers[mid] === target) {
            return mid;
        } else if (numbers[mid] < target) {
            // Too small: throw away mid and everything left of it.
            left = mid + 1;
        } else {
            // Too big: throw away mid and everything right of it.
            right = mid - 1;
        }
    }

    return -1;
}
```

For a **first position** or **binary search on the answer**, find the first "yes". The answers must look like no, no, no, yes, yes.

```js
// The smallest value from low to high where works(value) is true.
function findFirstYes(low, high, works) {
    let left = low;
    let right = high;

    // Stays -1 if no value works.
    let answer = -1;

    while (left <= right) {
        const mid = left + Math.floor((right - left) / 2);

        if (works(mid)) {
            // A yes. Save it, then look for an earlier one.
            answer = mid;
            right = mid - 1;
        } else {
            left = mid + 1;
        }
    }

    return answer;
}
```

### BFS on a graph or a grid

BFS goes ring by ring, so the first time it reaches a node is by the fewest steps. O(V + E) time, O(V) space.

```js
// Fewest steps from start to every node. -1 = not reached.
function bfs(graph, start) {
    const distance = new Array(graph.length).fill(-1);
    distance[start] = 0;

    // An array + a head index. shift() would be O(n).
    const queue = [start];
    let head = 0;

    while (head < queue.length) {
        const node = queue[head];
        head++;

        for (const neighbor of graph[node]) {
            // Mark it when you ADD it, so it is added only once.
            if (distance[neighbor] === -1) {
                distance[neighbor] = distance[node] + 1;
                queue.push(neighbor);
            }
        }
    }

    return distance;
}
```

On a grid, a cell's neighbors come from a `directions` array. Check the bounds first.

```js
// Up, down, left, right, as [row change, col change].
const directions = [[-1, 0], [1, 0], [0, -1], [0, 1]];

function getNeighbors(grid, row, col) {
    const neighbors = [];

    for (const [rowChange, colChange] of directions) {
        const newRow = row + rowChange;
        const newCol = col + colChange;

        // Skip cells outside the grid.
        const insideRows = newRow >= 0 && newRow < grid.length;
        const insideCols = newCol >= 0 && newCol < grid[0].length;

        if (insideRows && insideCols) {
            neighbors.push([newRow, newCol]);
        }
    }

    return neighbors;
}
```

Grid BFS: the queue holds `[row, col]` pairs, `getNeighbors(grid, row, col)` replaces `graph[node]`, and visited is a Set of strings like `"2,3"` (or change the cell itself). Many starting cells? Put them **all** in the queue at the start.

### DFS

Go deep first, then come back. One DFS from each unvisited node counts the separate groups. O(V + E) time.

```js
function dfs(graph, node, visited) {
    visited.add(node);

    for (const neighbor of graph[node]) {
        if (!visited.has(neighbor)) {
            dfs(graph, neighbor, visited);
        }
    }
}

// Each unvisited node starts a new group (island).
function countGroups(graph) {
    const visited = new Set();
    let groups = 0;

    for (let node = 0; node < graph.length; node++) {
        if (!visited.has(node)) {
            groups++;
            dfs(graph, node, visited);
        }
    }

    return groups;
}
```

On a tree, decide what one call returns for its subtree, and what it returns for `null`. Then trust the calls. O(n) time, O(h) space.

```js
function maxDepth(node) {
    if (node === null) {
        return 0;
    }

    const leftDepth = maxDepth(node.left);
    const rightDepth = maxDepth(node.right);

    return 1 + Math.max(leftDepth, rightDepth);
}
```

Very deep input (a big grid)? Recursion overflows near 10,000 calls. Use your own stack: an array with `push` and `pop`.

### Backtracking

Choose, explore, undo. Subsets are O(n · 2ⁿ).

```js
function subsets(nums) {
    const result = [];
    const path = [];

    function backtrack(start) {
        // Save a COPY. path itself keeps changing.
        result.push([...path]);

        for (let i = start; i < nums.length; i++) {
            path.push(nums[i]);
            backtrack(i + 1);
            path.pop();
        }
    }

    backtrack(0);
    return result;
}
```

| Problem | Change |
| --- | --- |
| Each item once (subsets, combinations) | `backtrack(i + 1)` |
| Items can be reused (combination sum) | `backtrack(i)` |
| Order matters (permutations) | Loop from 0 every time, with a `used` array |
| The input has duplicates | Sort first, skip `nums[i] === nums[i - 1]` when `i > start` |

### 1D dynamic programming

The recipe: **1.** what `dp[i]` means, **2.** the recurrence, **3.** the base cases, **4.** the order of filling and where the answer is. Big O = cells × work per cell.

```js
// House Robber. dp[i] = the most money from the first i houses.
function rob(houses) {
    const count = houses.length;
    const dp = new Array(count + 1).fill(0);

    // Base cases: no houses, then only the first house.
    dp[0] = 0;
    dp[1] = houses[0];

    for (let i = 2; i <= count; i++) {
        // Skip house i, or rob it. House i is at index i - 1.
        const skip = dp[i - 1];
        const take = dp[i - 2] + houses[i - 1];
        dp[i] = Math.max(skip, take);
    }

    return dp[count];
}
```

`dp[i]` only reads the last two cells? Keep two variables instead: O(1) space.

### Topological sort

Kahn's algorithm. O(V + E) time and space.

**Step 1: build the graph and count the in-degrees.** In-degree = how many tasks a node still waits for.

```js
// [from, to] means: from must come before to.
function buildGraph(nodeCount, edges) {
    const graph = Array.from({ length: nodeCount }, () => []);
    const indegree = new Array(nodeCount).fill(0);

    for (const [from, to] of edges) {
        graph[from].push(to);
        indegree[to]++;
    }

    return { graph, indegree };
}
```

**Step 2: find the nodes that wait for nothing.** Loop over **all** nodes, so nodes with no edges are not forgotten.

```js
function findReadyNodes(indegree) {
    const ready = [];

    for (let node = 0; node < indegree.length; node++) {
        if (indegree[node] === 0) {
            ready.push(node);
        }
    }

    return ready;
}
```

**Step 3: take the ready nodes one by one.** The queue fills up in a valid order, so it is also the answer.

```js
function topologicalSort(graph, indegree) {
    const queue = findReadyNodes(indegree);
    let head = 0;

    while (head < queue.length) {
        const node = queue[head];
        head++;

        // node is done, so each node after it waits for one less.
        for (const next of graph[node]) {
            indegree[next]--;
            if (indegree[next] === 0) {
                queue.push(next);
            }
        }
    }

    // Shorter than graph.length? Some nodes are stuck in a loop.
    return queue;
}
```

Course Schedule's `[a, b]` means "a needs b", so the arrow is **b → a**.

### Union-find

`parent[i]` points up, and a root points to itself. Same group means `find(a) === find(b)`. Write these inside your solution, where `count` is the number of items.

```js
// [0, 1, 2, ...]: every item starts as its own root.
const parent = Array.from({ length: count }, (_, index) => index);

function find(item) {
    if (parent[item] !== item) {
        // Path compression: point item straight at its root.
        parent[item] = find(parent[item]);
    }

    return parent[item];
}

// Returns false when the two are already in the same group.
function union(itemA, itemB) {
    const rootA = find(itemA);
    const rootB = find(itemB);

    if (rootA === rootB) {
        return false;
    }

    parent[rootB] = rootA;
    return true;
}
```

Add **union by size** (hang the smaller group under the bigger root) and each call is almost O(1). The full class is in [Union-Find](./graphs/union-find.mdx#the-unionfind-class). `union` returning `false` means that edge closes a loop.

### Heap

JavaScript has no heap. The API: `new MinHeap()`, `push(value)` O(log n), `pop()` O(log n), `peek()` O(1), `size()` O(1). The full class is in [Heaps and Priority Queues](./heaps/heaps.mdx#writing-a-minheap-in-javascript). For pairs or a max-heap, use the `Heap` with a compare function from [Top K and Merge K](./heaps/top-k.mdx).

```js
// The k largest numbers: keep a min-heap of size k.
// Its top is the smallest of the big ones: the next to throw out.
const heap = new MinHeap();

for (const number of numbers) {
    heap.push(number);

    if (heap.size() > k) {
        heap.pop();
    }
}
```

O(n log k) time, O(k) space. A quick max-heap for numbers: push `-number`, and flip the sign back when you read it.

## Big O in JavaScript

Full lesson: [Big O Notation](./foundations/big-o.mdx).

**Built-in operations**

| Operation | Time | Why |
| --- | --- | --- |
| `arr[i]`, `arr.length`, `push`, `pop` | O(1) | works at the end; `push` is amortized O(1) |
| `shift`, `unshift`, `splice` | **O(n)** | every other item moves |
| `includes`, `indexOf`, `find`, `findIndex` | **O(n)** | a hidden loop |
| `slice`, `[...arr]`, `concat`, `reverse`, `join` | O(n) | a copy or one pass |
| `map`, `filter`, `forEach`, `reduce` | O(n) | one pass |
| `sort`, `toSorted` | O(n log n) | |
| `map.get`, `map.set`, `map.has`, `map.delete` | O(1) on average | hashing jumps to the right spot |
| `set.add`, `set.has`, `set.delete` | O(1) on average | same as a Map, keys only |
| `obj[key]`, `key in obj`, `delete obj[key]` | O(1) on average | objects are hash tables too |
| `map.size`, `set.size` | O(1) | stored, not counted |
| `Object.keys`, `Object.values`, `Object.entries` | O(n) | builds a new array |
| `new Set(arr)`, `[...new Set(arr)]` | O(n) | one pass |
| `str[i]`, `str.length` | O(1) | same as an array |
| `str.slice`, `split`, `includes`, `indexOf`, `str + other` | O(n) | walks or copies the characters |

**Data structures**

| Structure | Read or find | Add | Remove |
| --- | --- | --- | --- |
| Array | by index O(1), a value O(n) | end O(1), front or middle O(n) | end O(1), front or middle O(n) |
| Map, Set, object | O(1) on average | O(1) on average | O(1) on average |
| Stack (array) | top O(1) | `push` O(1) | `pop` O(1) |
| Queue (array + head index) | front O(1) | `push` O(1) | `head++` O(1) |
| Linked list | O(n) | O(1) at the head or after a known node | O(1) after a known node |
| Heap | top O(1), any value O(n) | O(log n) | top O(log n) |
| Binary search tree | O(h) | O(h) | O(h) |
| Trie | O(L) | O(L) | O(L) |
| Union-find | `find` almost O(1) | `union` almost O(1) | |

h = tree height: about log n when balanced, n when the tree is a chain. L = the word's length. Union-find is almost O(1) with path compression and union by size.

| Pattern | Time | Extra space |
| --- | --- | --- |

| Binary search | O(log n) | O(1) |

| Dijkstra | O(E log V) | O(V + E) |

## JavaScript gotchas

| Trap | Don't | Do |
| --- | --- | --- |
| Sorting numbers | `nums.sort()` sorts as text: `[10, 9, 1]` becomes `[1, 10, 9]` | `nums.sort((a, b) => a - b)`. It changes the array. |
| Taking from the front | `queue.shift()` is O(n), so BFS becomes O(V²) | An array + a head index: read `queue[head]`, then `head++` |
| Heaps | Look for a built-in heap. JavaScript has none | Write a small `MinHeap`, or ask "can I assume a heap?" |
| Saving a backtracking path | `result.push(path)`: every answer is the same array, empty at the end | `result.push([...path])` |
| Counting and lookups | An object: keys become strings (`obj[1]` is `obj["1"]`), and it has built-in keys like `"toString"` | A `Map`: any key type, keeps the order you added, has `size` |
| Using a Map | `map[key] = value` | `map.set(key, value)` and `map.get(key)` |
| Counting from zero | `counts.get(item) + 1` is `NaN` the first time | `(counts.get(item) \|\| 0) + 1` |
| A grid or a list of lists | `new Array(n).fill([])`: every row is the same array | `Array.from({ length: n }, () => [])` |
| Arrays as keys | `seen.add([2, 3])`: arrays match by reference, so `seen.has([2, 3])` is `false` | A string key: `seen.add(row + "," + col)` |
| The middle index | `(left + right) / 2` can give a decimal | `left + Math.floor((right - left) / 2)` |
| Starting a min or max | `let smallest = 0` | `Infinity` for a min, `-Infinity` for a max |
| Building a long string | `result += letter` in a loop | Push the pieces into an array, then `join("")` once |
| Very deep recursion | Recursive DFS on a huge grid: stack overflow near 10,000 calls | Your own stack: an array with `push` and `pop` |
| Comparing number strings | `"10" < "9"` is `true` | Turn them into numbers first: `Number("10")` |
