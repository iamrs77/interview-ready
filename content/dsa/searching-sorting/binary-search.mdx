## The idea

Binary search finds an item in a **sorted** list by checking the **middle** first. The middle tells you which half the item must be in, so you throw the other half away. Then you do the same on the half that is left, again and again.

Think of the **number guessing game**. I pick a number from 1 to 100. You guess 50. I say "higher". Now you know it's between 51 and 100, so you guess 75. "Lower." You guess 62, and so on. Each guess cuts the possible numbers in half, so you never need more than 7 guesses. Guessing 1, 2, 3... in order could take 100.

- "Higher" or "lower" only helps because the numbers are **in order**. Binary search **needs sorted data**.
- Each guess **halves** what is left. That is what makes it fast: **O(log n)**.

## How it works

### A sorted array and three indexes

Here is a sorted array, with the index of each item:

```js
const numbers = [1, 3, 5, 7, 9, 11, 13];
```

| index | 0 | 1 | 2 | 3 | 4 | 5 | 6 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| value | 1 | 3 | 5 | 7 | 9 | 11 | 13 |

We keep three indexes:

- `left`: the first index that could still hold the target.
- `right`: the last index that could still hold the target.
- `mid`: the index halfway between them. This is the one we check.

Everything from `left` to `right` (both ends included) is **still possible**. Everything outside has been thrown away.

At each step, compare `numbers[mid]` with the target:

- **Equal:** found it. Return `mid`.
- **`numbers[mid]` is smaller:** the target is bigger, so it can only be on the right. Move `left = mid + 1`.
- **`numbers[mid]` is bigger:** the target can only be on the left. Move `right = mid - 1`.

Stop when `left` passes `right`. Nothing is left to check, so the target isn't there.

### Step by step

Find **13**:

| Step | left | right | mid | numbers[mid] | Compared with 13 | Next |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | 0 | 6 | 3 | 7 | smaller | left = 4 |
| 2 | 4 | 6 | 5 | 11 | smaller | left = 6 |
| 3 | 6 | 6 | 6 | 13 | equal | return 6 |

In step 3, `left` and `right` are the same index. One item is still possible, so we must check it. That is why the loop runs **while `left <= right`**, not `left < right`.

Find **4**, which is not in the array:

| Step | left | right | mid | numbers[mid] | Compared with 4 | Next |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | 0 | 6 | 3 | 7 | bigger | right = 2 |
| 2 | 0 | 2 | 1 | 3 | smaller | left = 2 |
| 3 | 2 | 2 | 2 | 5 | bigger | right = 1 |
| 4 | 2 | 1 | | | left passed right | return -1 |

### The code

This is the same thing as code. It returns the index of the target, or -1.

```js
function binarySearch(numbers, target) {
    let left = 0;
    let right = numbers.length - 1;

    while (left <= right) {
        const mid = left + Math.floor((right - left) / 2);

        if (numbers[mid] === target) {
            return mid;
        }

        if (numbers[mid] < target) {
            // Too small: throw away mid and everything left of it.
            left = mid + 1;
        } else {
            // Too big: throw away mid and everything right of it.
            right = mid - 1;
        }
    }

    // left passed right: nothing is left to check.
    return -1;
}

const sortedNumbers = [1, 3, 5, 7, 9, 11, 13];
console.log(binarySearch(sortedNumbers, 13)); // 6
console.log(binarySearch(sortedNumbers, 4)); // -1
```

**Time:** O(log n), because every step throws away half of what is left. **Space:** O(1), because we only keep three numbers: `left`, `right` and `mid`.

### Why it's O(log n)

`log n` is how many times you can cut `n` in half before one item is left (see [Big O Notation](../foundations/big-o.mdx)). In the worst case:

| Items | Checking one by one | Binary search |
| --- | --- | --- |
| 8 | 8 checks | 4 checks |
| 1,000 | 1,000 | 10 |
| 1,000,000 | 1,000,000 | 20 |
| 1,000,000,000 | 1,000,000,000 | 30 |

Double the items, and binary search needs just **one more** check.

### Why mid = left + Math.floor((right - left) / 2)

This line has two jobs.

**1. `Math.floor` makes it a whole number.** With `left = 0` and `right = 5`, the middle is 2.5. There is no index 2.5, so `items[2.5]` is `undefined`. `Math.floor` rounds down to 2.

```js
const items = [10, 20, 30, 40, 50, 60];

console.log((0 + 5) / 2); // 2.5
console.log(items[2.5]); // undefined
console.log(Math.floor((0 + 5) / 2)); // 2
```

**2. `left + ...` can't overflow.** Read it as: "start at `left`, then walk half the distance to `right`". It gives the same index as `(left + right) / 2`. Why the longer form? In Java and C++, a normal whole number (an `int`) can't go above about 2.1 billion. If `left` and `right` are both big, `left + right` goes past that limit and wraps around to a negative number. `right - left` is never bigger than `right`, so it stays safe.

```js
const left = 2000000000;
const right = 2100000000;

// "| 0" squeezes a number into 32 bits, like an int in Java.
const wrappedSum = (left + right) | 0;
console.log(wrappedSum); // -194967296

const safeMid = left + Math.floor((right - left) / 2);
console.log(safeMid); // 2050000000
```

In JavaScript, numbers stay exact up to about 9 quadrillion (`Number.MAX_SAFE_INTEGER`), so `Math.floor((left + right) / 2)` works too. Use the safe form anyway: it works in every language, and interviewers notice it.

## The template that avoids off-by-one bugs

Most binary search bugs are **off by one**: the loop stops one step too early, or never stops at all. Use the same shape every time, and these bugs go away.

### Four rules

1. **Start with `right = numbers.length - 1`.** That is the last real index. Both ends are still possible.
2. **Loop `while (left <= right)`.** When `left === right`, one item is still possible, so check it.
3. **Always move past `mid`:** `left = mid + 1` or `right = mid - 1`. You have already checked `mid`, so throw it away. If you write `left = mid`, the loop can run forever: with `left = 2` and `right = 3`, `mid` is 2, so `left` stays 2.
4. **Looking for the first or last match? Save it in `answer` and keep going.** Don't stop at the first match you see.

### Finding the first "yes"

Many problems don't ask "is the target here?". They ask "where does it **start**?". For example: in `[1, 3, 5, 5, 5, 8, 9]`, where is the **first** 5?

Ask the same yes/no question at every index: "is the value 5 or more?"

| index | 0 | 1 | 2 | 3 | 4 | 5 | 6 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| value | 1 | 3 | 5 | 5 | 5 | 8 | 9 |
| value >= 5? | no | no | **yes** | yes | yes | yes | yes |

The array is sorted, so the answers are all "no" first, then all "yes". We want the spot where "no" turns into "yes": the **first yes**. Binary search finds it like this:

- `mid` is a **yes**: it might be the first one. Save `answer = mid`, then look for an earlier yes on the left: `right = mid - 1`.
- `mid` is a **no**: the first yes must be on the right: `left = mid + 1`.

```js
// Returns the first index whose value is >= target.
// If every value is smaller, returns numbers.length.
function findFirstAtLeast(numbers, target) {
    let left = 0;
    let right = numbers.length - 1;

    // If we never see a "yes", the answer is "just after the end".
    let answer = numbers.length;

    while (left <= right) {
        const mid = left + Math.floor((right - left) / 2);

        if (numbers[mid] >= target) {
            // A "yes". Save it, then look for an earlier one.
            answer = mid;
            right = mid - 1;
        } else {
            // A "no". The first "yes" is further right.
            left = mid + 1;
        }
    }

    return answer;
}
```

Here it is on our array. The answer moves left each time we find an earlier "yes":

| Step | left | right | mid | numbers[mid] | >= 5? | answer |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | 0 | 6 | 3 | 5 | yes | 3, then right = 2 |
| 2 | 0 | 2 | 1 | 3 | no | 3, then left = 2 |
| 3 | 2 | 2 | 2 | 5 | yes | 2, then right = 1 |
| 4 | 2 | 1 | | | stop | **2** |

```js
const sorted = [1, 3, 5, 5, 5, 8, 9];

console.log(findFirstAtLeast(sorted, 5)); // 2
console.log(findFirstAtLeast(sorted, 6)); // 5
console.log(findFirstAtLeast(sorted, 10)); // 7
```

This one function answers several common questions:

| Question | How | Result |
| --- | --- | --- |
| Where is the first 5? | `findFirstAtLeast(sorted, 5)`, then check the value there is really 5 | 2 |
| Where is the last 5? | the first value that is 6 or more, minus one | 4 |
| Where would 6 go to keep the array sorted? ("Search Insert Position") | `findFirstAtLeast(sorted, 6)` | 5 |
| How many 5s are there? | first 6 or more, minus first 5 or more | 3 |

The first question needs the extra check, because 4 is not in the array but `findFirstAtLeast` still returns a spot for it:

```js
function firstPosition(numbers, target) {
    const index = findFirstAtLeast(numbers, target);

    // The spot must be inside the array and hold the target.
    if (index < numbers.length && numbers[index] === target) {
        return index;
    }

    return -1;
}

console.log(firstPosition(sorted, 5)); // 2
console.log(firstPosition(sorted, 4)); // -1

// The last 5 sits just before the first value that is 6 or more.
console.log(findFirstAtLeast(sorted, 6) - 1); // 4
```

The "last position" trick (search for `target + 1`) works when the values are whole numbers.

## Binary search on the answer

Sometimes there is no array to search. Instead, the answer is **a number in a range**, and you must find the smallest one that works.

Example: Koko must eat all her bananas in 8 hours. What is the **slowest eating speed** that still works?

- A speed that is too slow fails. A speed that is fast enough works, and **every faster speed works too**.
- So if you check speeds 1, 2, 3, 4... the answers look like: no, no, no, yes, yes, yes.
- That is the same "first yes" shape as above. Only now we search over **possible answers**, not array indexes.

Set it up with three questions:

1. **What is the smallest possible answer?** That is `left`.
2. **What is the largest possible answer?** That is `right`.
3. **How do I check if one answer works?** Write a small helper for it. It's usually a simple O(n) loop.

Then use the first-yes template, and call the helper where you used to look at `numbers[mid]`. Instead of trying every speed from 1 to a billion, you try about 30. Problem 3 below writes it out in full.

## Classic problems

### 1. Search in Rotated Sorted Array

**Problem:** a sorted array of different numbers was **rotated**: some items from the front were moved to the back. `[0, 1, 2, 4, 5, 6, 7]` might become `[4, 5, 6, 7, 0, 1, 2]`. Find the index of `target` in O(log n), or return -1. Searching for 0 gives 4.

**Idea:** a rotated array is two sorted pieces, one after the other:

| index | 0 | 1 | 2 | 3 | 4 | 5 | 6 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| value | 4 | 5 | 6 | 7 | 0 | 1 | 2 |
| piece | first | first | first | first | second | second | second |

Cut it at any `mid`, and **at least one half is fully sorted**. Find that half, and it's easy to check whether the target is inside it: is it between that half's first and last values?

- If `numbers[left] <= numbers[mid]`, the **left half** (`left` to `mid`) is sorted.
- Otherwise, the **right half** (`mid` to `right`) is sorted.
- Target inside the sorted half? Search there. If not, search the other half.

```js
function searchRotated(numbers, target) {
    let left = 0;
    let right = numbers.length - 1;

    while (left <= right) {
        const mid = left + Math.floor((right - left) / 2);

        if (numbers[mid] === target) {
            return mid;
        }

        if (numbers[left] <= numbers[mid]) {
            // The left half is sorted. Is the target inside it?
            if (numbers[left] <= target && target < numbers[mid]) {
                right = mid - 1;
            } else {
                left = mid + 1;
            }
        } else {
            // The right half is sorted. Is the target inside it?
            if (numbers[mid] < target && target <= numbers[right]) {
                left = mid + 1;
            } else {
                right = mid - 1;
            }
        }
    }

    return -1;
}
```

How it finds 0 in `[4, 5, 6, 7, 0, 1, 2]`:

| Step | left | right | mid | numbers[mid] | Sorted half | Is 0 inside it? | Next |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | 0 | 6 | 3 | 7 | left: 4 to 7 | no | left = 4 |
| 2 | 4 | 6 | 5 | 1 | left: 0 to 1 | yes | right = 4 |
| 3 | 4 | 4 | 4 | 0 | | found | return 4 |

```js
const rotated = [4, 5, 6, 7, 0, 1, 2];

console.log(searchRotated(rotated, 0)); // 4
console.log(searchRotated(rotated, 5)); // 1
console.log(searchRotated(rotated, 3)); // -1
console.log(searchRotated([1], 0)); // -1
```

**Time:** O(log n) · **Space:** O(1). Every step still throws away half of the array; we just need one extra check to pick the half.

### 2. Find Minimum in Rotated Sorted Array

**Problem:** the same kind of rotated array, all numbers different. Return the smallest number in O(log n). `[4, 5, 6, 7, 0, 1, 2]` gives 0, and `[3, 4, 5, 1, 2]` gives 1.

**Idea:** compare every value with the **last** value. Every value in the first piece is bigger than the last value. Every value in the second piece is smaller than or equal to it.

| index | 0 | 1 | 2 | 3 | 4 | 5 | 6 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| value | 4 | 5 | 6 | 7 | 0 | 1 | 2 |
| `value <= 2`? | no | no | no | no | **yes** | yes | yes |

The minimum is the start of the second piece: the **first yes**. That is the template from above, with a new question.

```js
function findMin(numbers) {
    const last = numbers[numbers.length - 1];

    let left = 0;
    let right = numbers.length - 1;

    // The last index is always a "yes", so start there.
    let answer = numbers.length - 1;

    while (left <= right) {
        const mid = left + Math.floor((right - left) / 2);

        if (numbers[mid] <= last) {
            // In the second piece. Save it, look further left.
            answer = mid;
            right = mid - 1;
        } else {
            // Still in the first piece. Go right.
            left = mid + 1;
        }
    }

    return numbers[answer];
}

console.log(findMin([4, 5, 6, 7, 0, 1, 2])); // 0
console.log(findMin([3, 4, 5, 1, 2])); // 1
console.log(findMin([11, 13, 15, 17])); // 11
```

If the array was not rotated at all, every value is a "yes", and the answer is index 0.

**Time:** O(log n) · **Space:** O(1). It's the first-yes search, which halves the range each step.

### 3. Koko Eating Bananas

**Problem:** there are piles of bananas, for example `[3, 6, 7, 11]`, and Koko has `8` hours. Each hour she picks one pile and eats up to `speed` bananas from it. If the pile has fewer, she finishes it and rests for the rest of that hour. Return the **slowest** speed that lets her finish in time. Here it's 4.

**Idea:** binary search on the answer.

- At a given speed, a pile of 7 takes `Math.ceil(7 / speed)` hours. Add that up for all piles.
- Smallest possible speed: **1**. Largest useful speed: **the biggest pile**, because then every pile takes exactly one hour, and faster can't help.
- Faster speeds always need the same or fewer hours, so "finishes in time?" goes no, no, ..., yes, yes. Find the first yes.

| Speed | 1 | 2 | 3 | 4 | 5 | 6 |
| --- | --- | --- | --- | --- | --- | --- |
| Hours needed | 27 | 15 | 10 | 8 | 8 | 6 |
| 8 hours or less? | no | no | no | **yes** | yes | yes |

**Step 1: the check.** How many hours does a speed need?

```js
function hoursNeeded(piles, speed) {
    let hours = 0;

    for (const pile of piles) {
        // A pile of 7 at speed 3 takes 3 hours: 3 + 3 + 1.
        hours = hours + Math.ceil(pile / speed);
    }

    return hours;
}

console.log(hoursNeeded([3, 6, 7, 11], 3)); // 10
console.log(hoursNeeded([3, 6, 7, 11], 4)); // 8
```

**Step 2: binary search over the speeds.**

```js
function minEatingSpeed(piles, hoursLimit) {
    let left = 1;

    // Math.max(...piles) gives the biggest pile.
    let right = Math.max(...piles);

    let answer = right;

    while (left <= right) {
        const speed = left + Math.floor((right - left) / 2);

        if (hoursNeeded(piles, speed) <= hoursLimit) {
            // Fast enough. Save it, then try slower speeds.
            answer = speed;
            right = speed - 1;
        } else {
            // Too slow. Try faster speeds.
            left = speed + 1;
        }
    }

    return answer;
}

console.log(minEatingSpeed([3, 6, 7, 11], 8)); // 4
console.log(minEatingSpeed([30, 11, 23, 4, 20], 5)); // 30
console.log(minEatingSpeed([30, 11, 23, 4, 20], 6)); // 23
```

How it finds 4 for `[3, 6, 7, 11]` and 8 hours:

| Step | left | right | speed | hours needed | 8 or less? | answer |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | 1 | 11 | 6 | 6 | yes | 6, then right = 5 |
| 2 | 1 | 5 | 3 | 10 | no | 6, then left = 4 |
| 3 | 4 | 5 | 4 | 8 | yes | 4, then right = 3 |
| 4 | 4 | 3 | | | stop | **4** |

**Time:** O(n log m), where `n` is the number of piles and `m` is the biggest pile. We try about log m speeds, and each check walks through all `n` piles. **Space:** O(1).

The same shape solves "Capacity to Ship Packages Within D Days", "Split Array Largest Sum" and "Minimum Number of Days to Make Bouquets". Only the check changes.

## How to spot it

- The array is **sorted**, or sorted and rotated, and you must **find** something in it.
- The problem says **O(log n)**, or the input is huge and O(n) is too slow.
- The question asks for the **first** or **last** position, or where to **insert** something.
- "Find the **minimum** speed / capacity / days **such that** ..." or "the **maximum** value that still works". That is binary search on the answer.
- The possible answers go up to 10⁹, so trying them one by one is too slow, but **checking one answer** is easy.
- Once an answer works, every bigger answer works too (or every smaller one).
- A **sorted grid**, where each row starts after the row above ends (Search a 2D Matrix): treat it as one long sorted array of `rows * cols` items. Index `i` is the cell `matrix[Math.floor(i / cols)][i % cols]`.

## Common mistakes

- **`while (left < right)` with `right = length - 1`.** The last remaining item never gets checked. Use `<=`.
- **`left = mid` or `right = mid` in a `<=` loop.** When `left` and `right` meet, nothing changes, and the loop runs forever. Move to `mid + 1` or `mid - 1`.
- **Forgetting `Math.floor`.** `mid` becomes 2.5, and `numbers[2.5]` is `undefined`.
- **Stopping at the first match** when the question asks for the first or last position. Save `answer` and keep searching.
- **Binary searching an unsorted array.** The halves mean nothing. Sort it first (O(n log n)), or use a hash map.
- **`<` instead of `<=` in `numbers[left] <= numbers[mid]`** (rotated search). When `left === mid`, the left half is one item, which counts as sorted. With `<`, searching `[3, 1]` for 1 returns -1.
- **Starting binary search on the answer at 0.** Koko's speed 0 means dividing by zero. Start at the smallest answer that makes sense.

## In the interview

- Say why binary search fits: "The array is sorted, so I can check the middle and throw away half each time."
- Say what `left` and `right` mean: "The answer is always somewhere between `left` and `right`."
- Test with small cases: an empty array, one item, a target smaller than everything, bigger than everything, and duplicates.

> "Speeds from 1 to the biggest pile are possible, and if a speed works, every faster speed works too. So I'll binary search over the speeds. For each middle speed I count the hours in O(n). If it's fast enough, I save it and try slower; if not, I try faster. That's O(n log m) time and O(1) space."

**Likely follow-up:** "What if the rotated array can have duplicates?"

**Answer:** "Then `numbers[left]`, `numbers[mid]` and `numbers[right]` can all be equal, like in `[1, 1, 1, 0, 1]`, and I can't tell which half is sorted. In that case I move `left` one step forward and try again. It still works, but the worst case becomes O(n)."

<Callout title="Remember this" type="success">
  - **Binary search = check the middle, throw away half.** It needs sorted data (or a yes/no check that flips only once). 1,000,000 items → about 20 checks.
  - **The template:** `right = length - 1`, `while (left <= right)`, then `left = mid + 1` or `right = mid - 1`.
  - `mid = left + Math.floor((right - left) / 2)`: **floor** for a whole index, and the `left +` form never overflows.
  - For **first / last / insert position**, save `answer = mid` and keep searching.
  - **Rotated array:** one half is always sorted. Check if the target is inside that half.
  - **"Smallest speed / capacity that works"** → binary search on the answer, with a small check function.
