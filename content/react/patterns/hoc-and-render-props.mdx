## The idea

Before hooks, React code shared logic between components in two ways:

- A **higher-order component (HOC)**: a **function** that takes a component and returns a **new component** with extra behavior.
- A **render prop**: a component that takes a **function as a prop**, and calls it to decide what to render.

Think of a **gift-wrapping service**. You hand over a present and get it back wrapped, with a card attached. The present inside is untouched. An HOC does the same to your component. Today custom hooks do most of this job, but interviewers still ask about both patterns.

## Higher-order components

An HOC is a plain **function**, usually named **`withSomething`**. It takes a component and returns a **new component** that renders the original one. It **doesn't change** the original, it **wraps** it. The name comes from [higher-order functions](../../javascript/functions/higher-order-functions-and-currying.mdx) in JavaScript.

```jsx
function withExtraProp(WrappedComponent) {
    // Return a new component.
    function WithExtraProp(props) {
        const extra = "I am an extra prop!";

        // Render the original, with all its props plus the extra one.
        return <WrappedComponent {...props} extra={extra} />;
    }

    return WithExtraProp;
}
```

Using it:

```jsx
function Display({ name, extra }) {
    return (
        <div>
            <p>Name: {name}</p>
            <p>Extra: {extra}</p>
        </div>
    );
}

// Make the wrapped version once, outside any component.
const EnhancedDisplay = withExtraProp(Display);

function App() {
    return <EnhancedDisplay name="Ana" />;
}
```

`App` only passed `name`. The HOC passed it on with `{...props}`, and added `extra` on the way through.

HOCs you've probably used: **`React.memo(Component)`**, which skips re-renders when the props are the same, React-Redux's **`connect`** and React Router 5's **`withRouter`**. Hooks like `useSelector` and `useNavigate` replaced the last two.

## Example: withLogger

An HOC can add behavior, not only props. This one logs when the wrapped component appears and disappears:

```jsx
import { useEffect } from "react";

function withLogger(WrappedComponent) {
    function WithLogger(props) {
        useEffect(() => {
            console.log(WrappedComponent.name + " mounted");

            return () => {
                console.log(WrappedComponent.name + " unmounted");
            };
        }, []);

        return <WrappedComponent {...props} />;
    }

    return WithLogger;
}
```

```jsx
import withLogger from "./hoc/withLogger";

function App() {
    return <div>Hello from App!</div>;
}

export default withLogger(App);
```

When `App` appears, the console shows `App mounted`. In development, Strict Mode runs effects twice, so you see `App mounted`, `App unmounted`, `App mounted`.

## Rules for writing HOCs

- **Pass all props through** with `{...props}`.
- **Don't change the original component.** Return a new one that renders it.
- **Never call an HOC during render.** Make the wrapped component **once**, at the top level of the file:

```jsx
function Parent() {
    // Wrong: a brand-new component type on every render of Parent.
    const LoggedCounter = withLogger(Counter);

    return <LoggedCounter />;
}
```

Each call to `withLogger` returns a **new** component type, so React throws the old `Counter` away and builds a new one: its **state resets** every time `Parent` renders.

- **Refs.** In React 19, `ref` is a normal prop, so `{...props}` passes it on. Before React 19, an HOC needed `forwardRef`.

## Render props

A **render prop** is a prop whose value is a **function that returns JSX**. The component does the work, then **calls your function** with the result to decide what to show.

```jsx
import { useState } from "react";

function MouseTracker({ render }) {
    const [position, setPosition] = useState({ x: 0, y: 0 });

    function handleMouseMove(event) {
        setPosition({ x: event.clientX, y: event.clientY });
    }

    return (
        <div onMouseMove={handleMouseMove} style={{ height: 300 }}>
            {render(position)}
        </div>
    );
}

function App() {
    return (
        <MouseTracker
            render={(position) => (
                <p>
                    The mouse is at {position.x}, {position.y}
                </p>
            )}
        />
    );
}
```

`MouseTracker` owns the **logic** (the state and the event). The parent decides the **look**. The function is often passed as **`children`** instead, and then `MouseTracker` calls `children(position)`.

## Why hooks replaced them

The same mouse logic as a custom hook:

```jsx
function useMousePosition() {
    const [position, setPosition] = useState({ x: 0, y: 0 });

    useEffect(() => {
        function handleMouseMove(event) {
            setPosition({ x: event.clientX, y: event.clientY });
        }

        window.addEventListener("mousemove", handleMouseMove);

        return () => window.removeEventListener("mousemove", handleMouseMove);
    }, []);

    return position;
}
```

A component just calls `const position = useMousePosition();`: no wrapper, no function prop. The problems hooks solved:

| Problem | HOCs | Render props | Hooks |
| --- | --- | --- | --- |
| **Wrapper hell**: extra layers in the component tree | `withA(withB(withC(Page)))` adds 3 layers | Each one adds a layer | **No** extra layers |
| **Where did this prop come from?** | Hidden: injected by some HOC | Clear: it's the function's argument | Clear: `const x = useX()` |
| **Name clashes** | Two HOCs adding `data`: one silently wins | No clash: you name the argument | No clash: you name the variable |
| **Nesting** | Fine to read | Functions inside functions, deeper and deeper | Flat: one call per line |

## Are they still used?

- **Older code and libraries**, with `connect`, `withRouter` or their own `withSomething` helpers.
- **Wrapping what renders.** A hook can't wrap a component in a boundary, so `withErrorBoundary(Component)` is still common, since [error boundaries](./error-boundaries.mdx) must be class components. Guards like `withAuth` are also still written as HOCs.
- **Render props for "how to draw each item"**, like `renderItem={(item) => <Row item={item} />}` in lists.

For **sharing logic**, reach for a [custom hook](../hooks/custom-hooks.mdx) first.

## Common mistakes

- **Calling the HOC inside a component.** A new component type each render, so the state resets. Wrap once, at the top level.
- **Forgetting `{...props}`.** Props from the parent never reach the wrapped component.
- **Two HOCs adding the same prop name.** One value is lost without any error.
- **A new render-prop function on every render with `React.memo`.** The function is a new object each time, so `memo` can't skip the render.

## In the interview

**Likely question:** "What is a higher-order component?"

> "A function that takes a component and returns a new component that renders the original with extra props or behavior, like `withAuth(Dashboard)` or `withLogger(App)`. It doesn't change the original, it wraps it, and passes all the props through. It was the main way to share logic between components before hooks. `React.memo` and React-Redux's `connect` are well-known HOCs."

**Likely follow-up:** "What's a render prop, and why did hooks replace both patterns?"

**Answer:** "A render prop is a function prop that a component calls to decide what to render: the component owns the logic and the caller owns the look. HOCs hide where props come from and can clash on prop names, and both patterns add extra layers to the tree, which leads to wrapper hell. A custom hook shares the same logic as a plain function call, with no extra layers. I still use HOCs to wrap rendering, like error boundaries, and render props for things like `renderItem` in lists."
