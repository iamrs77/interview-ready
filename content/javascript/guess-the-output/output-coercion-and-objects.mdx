## How to solve these

1. **`===` never converts. `==` converts first.** If both sides have the same type, `==` works like `===`. `null == undefined` is `true`, and they loosely equal nothing else. Otherwise, an object or array first becomes a string (`[]` → `""`, `[1, 2]` → `"1,2"`). Then booleans and strings become numbers. `NaN` equals nothing, not even itself.
2. **`+` with a string joins. Other math makes numbers.** `+` first turns objects into strings. Then, if either side is a string, it joins text. If not, it adds numbers. `-`, `*` and `/` always turn both sides into numbers.
3. **There are only 8 falsy values:** `false`, `0`, `-0`, `0n`, `""`, `null`, `undefined` and `NaN`. Everything else is truthy, even `[]`, `{}`, `"0"` and `"false"`.
4. **`typeof` has two surprises:** `typeof null` is `"object"`, and so is `typeof []`. `instanceof` checks whether the class's `prototype` object appears in the object's prototype chain.
5. **Objects are compared and copied by reference.** `===` on two objects asks "is this the same object?", not "do they look the same?". `const copy = original` copies the reference, not the object.

See [Types and Coercion](../core-basics/types-and-coercion.mdx) and [Value vs Reference](../core-basics/value-vs-reference.mdx).

## The puzzles

### 1. typeof

```js
console.log(typeof 42);
console.log(typeof "42");
console.log(typeof null);
console.log(typeof []);
console.log(typeof function () {});
console.log(typeof NaN);
console.log(typeof undefined);
```

<Accordions>
<Accordion title="Answer">

```text
number
string
object
object
function
number
undefined
```

- `typeof null` is `"object"`. It's a bug from the first version of JavaScript, kept so that old code doesn't break. Check for null with `value === null`.
- Arrays are objects, so `typeof []` is `"object"`. Use `Array.isArray(value)` to check for an array.
- Functions are objects too, but `typeof` gives them their own answer: `"function"`.
- `NaN` means "Not a Number", but its type is `number`. It's what failed math gives you, like `"abc" * 2`.

</Accordion>
</Accordions>

### 2. instanceof

```js
class Animal {}

class Dog extends Animal {}

const pet = new Dog();

console.log(pet instanceof Dog);
console.log(pet instanceof Animal);
console.log(pet instanceof Object);
console.log([] instanceof Array);
console.log([] instanceof Object);
console.log("hi" instanceof String);
```

<Accordions>
<Accordion title="Answer">

```text
true
true
true
true
true
false
```

- `instanceof` walks up the prototype chain. For `pet`, the chain is `Dog.prototype` → `Animal.prototype` → `Object.prototype`. All three are found.
- An array's chain is `Array.prototype` → `Object.prototype`.
- `"hi"` is a primitive string, not an object made with `new String("hi")`. It has no chain to walk, so the answer is `false`. For primitives, use `typeof`.

</Accordion>
</Accordions>

### 3. Plus joins, minus counts

```js
console.log(1 + "2");
console.log("5" - 2);
console.log("5" + 2 - 1);
console.log(true + 1);
console.log("3" * "4");
console.log(1 + 2 + "3");
```

<Accordions>
<Accordion title="Answer">

```text
12
3
51
2
12
33
```

| Code | Step by step | Result |
|---|---|---|
| `1 + "2"` | one side is a string, so `+` joins | `"12"` |
| `"5" - 2` | `-` only does math: `5 - 2` | `3` |
| `"5" + 2 - 1` | left to right: `"5" + 2` is `"52"`, then `"52" - 1` | `51` |
| `true + 1` | no strings, so `true` becomes `1` | `2` |
| `"3" * "4"` | `*` turns both into numbers | `12` |
| `1 + 2 + "3"` | left to right: `1 + 2` is `3`, then `3 + "3"` | `"33"` |

- `console.log` prints strings without quotes, so `"12"` and `12` look the same in the output.

</Accordion>
</Accordions>

### 4. 0.1 + 0.2

```js
console.log(0.1 + 0.2);
console.log(0.1 + 0.2 === 0.3);
```

<Accordions>
<Accordion title="Answer">

```text
0.30000000000000004
false
```

- Numbers are stored in binary (base 2). `0.1` and `0.2` can't be stored exactly in binary, just like 1/3 can't be written exactly in decimal (0.3333...).
- The tiny errors add up, so the sum is a little more than `0.3`.
- To compare, allow a tiny difference: `Math.abs(a - b) < Number.EPSILON`. For money, count whole cents (or paise) instead.

</Accordion>
</Accordions>

### 5. Truthy and falsy

```js
if ([]) {
    console.log("empty array is truthy");
}

if ("0") {
    console.log("the string 0 is truthy");
}

console.log(Boolean(""));
console.log(Boolean(" "));
console.log(!!NaN);
console.log([] == false);
```

<Accordions>
<Accordion title="Answer">

```text
empty array is truthy
the string 0 is truthy
false
true
false
true
```

- `[]` and `"0"` are not on the falsy list, so both `if` blocks run.
- `""` is falsy. But `" "` (one space) is not empty, so it's truthy.
- `!!` is two "not"s. It turns any value into its boolean. `NaN` is falsy.
- `[] == false` is `true`, even though `[]` is truthy! `==` doesn't check truthiness. It converts: `[]` → `""` → `0`, and `false` → `0`. Then `0 == 0`.

</Accordion>
</Accordions>

### 6. Loose equality (==)

```js
console.log(0 == "");
console.log(0 == "0");
console.log("" == "0");
console.log(null == undefined);
console.log(null == 0);
console.log(NaN == NaN);
```

<Accordions>
<Accordion title="Answer">

```text
true
true
false
true
false
false
```

| Code | What happens | Result |
|---|---|---|
| `0 == ""` | `""` becomes `0` | `true` |
| `0 == "0"` | `"0"` becomes `0` | `true` |
| `"" == "0"` | both are strings, so they are compared as text, with no conversion | `false` |
| `null == undefined` | a special rule | `true` |
| `null == 0` | `null` only loosely equals `undefined` | `false` |
| `NaN == NaN` | `NaN` equals nothing, not even itself | `false` |

- `0` equals both `""` and `"0"`, but `""` doesn't equal `"0"`. That's why most teams use `===`.
- To check for `NaN`, use `Number.isNaN(value)`.

</Accordion>
</Accordions>

### 7. Adding arrays and objects

```js
console.log("A:", [] + []);
console.log("B:", [] + {});
console.log("C:", [1, 2] + [3]);
console.log("D:", {} + "x");
console.log("E:", [5] * 2);
```

<Accordions>
<Accordion title="Answer">

```text
A:
B: [object Object]
C: 1,23
D: [object Object]x
E: 10
```

- `+` first turns each object into a string. An array becomes its items joined by commas: `[]` → `""`, `[1, 2]` → `"1,2"`. A plain object becomes `"[object Object]"`.
- A: `"" + ""` is an empty string, so nothing prints after `A:`.
- B: `"" + "[object Object]"`.
- C: `"1,2" + "3"` is `"1,23"`. Arrays are not added item by item.
- D: `"[object Object]" + "x"`.
- E: `*` wants numbers. `[5]` → `"5"` → `5`, so `5 * 2` is `10`.

</Accordion>
</Accordions>

### 8. Same contents, different objects

```js
const first = { id: 1 };
const second = { id: 1 };
const third = first;

console.log(first === second);
console.log(first === third);
console.log([1, 2] === [1, 2]);

third.id = 2;
console.log(first.id);
```

<Accordions>
<Accordion title="Answer">

```text
false
true
false
2
```

- `first` and `second` look the same, but they are two separate objects in memory. `===` asks "same object?", so `false`.
- `const third = first` copies the **reference**. Both names point to one object.
- Each `[1, 2]` makes a new array, so `false` again.
- `third.id = 2` changes that one shared object, so `first.id` is `2` too.

</Accordion>
</Accordions>

### 9. A spread copy is shallow

```js
const original = {
    title: "Book",
    tags: ["new"],
};

const copy = { ...original };

copy.title = "Notebook";
copy.tags.push("sale");

console.log(original.title);
console.log(original.tags);
```

<Accordions>
<Accordion title="Answer">

```text
Book
[ 'new', 'sale' ]
```

- `{ ...original }` makes a new outer object and copies each property's value into it.
- `title` is a string (a primitive), so `copy` gets its own value. Changing it doesn't touch `original`.
- `tags` is an array (an object), so only the **reference** is copied. Both objects share one array.
- For a deep copy, use `structuredClone(original)`. See [Value vs Reference](../core-basics/value-vs-reference.mdx).

</Accordion>
</Accordions>

### 10. Changing vs replacing inside a function

```js
function update(player) {
    player.score = 50;

    player = { score: 100 };
    player.score = 200;
}

const hero = { score: 10 };

update(hero);
console.log(hero.score);
```

<Accordions>
<Accordion title="Answer">

```text
50
```

- `update(hero)` passes a copy of the **reference**. Now `player` and `hero` point to the same object.
- `player.score = 50` changes that shared object, so `hero` sees it.
- `player = { score: 100 }` points the local name `player` at a brand-new object. `hero` still points to the old one.
- `player.score = 200` changes the new object, which nobody outside can see.

</Accordion>
</Accordions>

### 11. Objects as object keys

```js
const scores = {};
const keyA = { id: 1 };
const keyB = { id: 2 };

scores[keyA] = 10;
scores[keyB] = 20;

console.log(scores[keyA]);
console.log(Object.keys(scores));
```

<Accordions>
<Accordion title="Answer">

```text
20
[ '[object Object]' ]
```

- The keys of a plain object are always strings (or symbols). An object used as a key is turned into a string: `"[object Object]"`.
- So `keyA` and `keyB` become the **same** key. `scores[keyB] = 20` overwrites the `10`.
- `scores[keyA]` looks up `"[object Object]"` and finds `20`.
- To use objects as keys, use a `Map`.

</Accordion>
</Accordions>

### 12. Array quirks

```js
const numbers = [10, 1, 5, 100];
numbers.sort();
console.log(numbers);

const parsed = ["1", "2", "3"].map(parseInt);
console.log(parsed);
```

<Accordions>
<Accordion title="Answer">

```text
[ 1, 10, 100, 5 ]
[ 1, NaN, NaN ]
```

- `sort()` with no compare function turns the items into **strings** and sorts them like words in a dictionary. `"10"` comes before `"5"` because `"1"` comes before `"5"`.
- Fix: `numbers.sort((a, b) => a - b)` gives `[ 1, 5, 10, 100 ]`.
- `map` calls its callback with three arguments: the item, the index and the array. `parseInt` takes two: the text and the radix (the number base). So the index becomes the radix:

| Call | What it means | Result |
|---|---|---|
| `parseInt("1", 0)` | radix 0 means "use the default", base 10 | `1` |
| `parseInt("2", 1)` | base 1 is not allowed | `NaN` |
| `parseInt("3", 2)` | base 2 only has the digits 0 and 1 | `NaN` |

- Fix: `["1", "2", "3"].map(Number)`.

</Accordion>
</Accordions>

## In the interview

Don't just say the answer. Say the conversion rule, then apply it one step at a time.

> "`[] == false`: the types are different, so `==` converts. First the array becomes a string, an empty string. Then both sides become numbers: the empty string is 0 and `false` is 0. `0 == 0`, so it's `true`. That's why I use `===` in real code. It never converts, so there are no surprises."

**Likely follow-up:** "How would you check that two objects have the same contents?"

**Answer:** "`===` only checks if it's the same object. For simple data, I can compare `JSON.stringify` of both, but the keys must be in the same order. The proper way is a deep-equal function: check that both have the same keys, compare each value, and call itself for nested objects. Libraries like Lodash have `isEqual`, and test tools have `toEqual`."

<Callout title="Remember this" type="success">
  - `===` never converts. `==` converts: objects become strings, then booleans and strings become numbers. `null` only loosely equals `undefined`.
  - `+` with a string **joins**. `-`, `*` and `/` always turn things into **numbers**.
  - Only 8 falsy values. `[]`, `{}` and `"0"` are all **truthy**.
  - `typeof null` and `typeof []` are both `"object"`. Use `value === null` and `Array.isArray`.
  - Objects compare and copy **by reference**. Spread copies **one level** only.
  - `sort()` compares items as **strings**, and `map(parseInt)` passes the index as the radix.
</Callout>
