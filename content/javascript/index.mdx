## The three kinds of JavaScript questions

JavaScript interviews, for frontend, full-stack or Node.js roles, ask three kinds of questions:

| Kind | What it sounds like | Where to practice |
| --- | --- | --- |
| **Explain it** | "What is a closure?" "How does the event loop work?" "== vs ===?" | The lessons in sections 1 to 9, and 12 |
| **Write it** | "Write debounce." "Implement `Promise.all`." "Write your own `bind`." | [10. Write Your Own](./write-your-own/debounce-and-throttle.mdx) |
| **Guess the output** | "What does this code print, and in what order?" | [11. Guess the Output](./guess-the-output/output-scope-and-hoisting.mdx) |

The interviewer wants more than the right answer. They want to hear **why**: name the rule ("promises run before timers"), then walk through the code line by line.

## Practice with the JS Playground

Reading code is not enough. You remember it when you change it and run it.

- Every JavaScript code block that can run has a **Run** button. It opens the block in the **JS Playground** and runs it. If the block builds on earlier blocks on the page, Run puts them in front of it first.
- Change the code and run it again. Try to break it, then guess what will happen before you press Run.
- Open the playground any time with the button at the top of the sidebar, or with `` Ctrl+` ``.
- For "Guess the Output" puzzles: write down your answer first, then press Run to check.
